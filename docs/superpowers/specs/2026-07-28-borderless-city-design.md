# MirrorLife 无界城产品、技术与美术设计

日期：2026-07-28  
状态：待用户书面审阅  
基线提交：`fceef14`  
目标分支：`codex/borderless-city-design`

## 1. 决策摘要

MirrorLife 的优先级依次为：

1. 游戏流程完整、清楚并且好玩。
2. 视觉设计具有稳定、鲜明的世界规则。
3. 桌面端和移动端性能达到发布预算。

首期只实施：

- 无界城玩法模式。
- D「晴织镜城 / Sunweave Mirror City」首发皮肤。
- 当前真实 3D 室内、人物跟随、行走和旋转能力。
- 共享世界进度和可恢复的本地存档。

A/B/C 不在首期制作资产，但其游戏反馈语言、美术规范和 `SkinPack` 接口在本设计中固定，后续接入时不得复制或分叉游戏逻辑。

用户已确认：

- A/B/C/D 只是换肤，不是四款独立游戏。
- 人物、任务、关系、建筑状态、无界区块和室内进度全部共享。
- 无限探索在四套皮肤中都可用。
- 首期顺序为无界城内核 → D 晴织镜城 → A/B/C。
- 改造前必须保留并验证当前网站的完整备份。

## 2. 非目标

首期不做：

- 全 WebGL 无限 3D 城市。
- 四套皮肤同时制作。
- 所有远端居民持续运行逐帧 AI。
- 云端多人同步或跨设备世界同步。
- 用 2D billboard 冒充真实 3D 室内人物。
- 通过降低截图分辨率掩盖真实性能问题。
- 为单张宣传图牺牲行走、旋转、碰撞或地图可探索性。

## 3. 产品结构

MirrorLife 由三个正交层组成：

```text
共享人生档案
  + 无界城玩法模式
  + 当前选择的 SkinPack
```

共享人生档案保存：

- 玩家身份和人物形象。
- 关系记忆。
- 选择时间线。
- 核心任务进度。
- 已发现区域。
- 建筑和社区变化。
- 真实 3D 室内探索进度。

`SkinPack` 只改变：

- 建筑、道路、植被和人物地图资产。
- 色彩、材质、字体和 UI 装饰。
- 地图出现、选择反馈和奖励动画。
- 环境音、交互音和音乐编排。

`SkinPack` 不得改变：

- 选择结果。
- 可交互区域。
- 碰撞体。
- 任务条件。
- 关系数值。
- 存档结构。
- 建筑室内的权威世界坐标。

## 4. 游戏设计

### 4.1 核心承诺

玩家不是在浏览一张会动的地图，而是在进入一个会记住其选择、并用人物关系和空间变化回应的社会。

每个可玩现场必须包含：

1. 一个可以被理解的人。
2. 一个没有标准答案的矛盾。
3. 一个玩家可以亲自靠近的地点。
4. 一个会付出代价的选择。
5. 一个立即可见的局部后果。
6. 一个稍后扩散的社会后果。

### 4.2 三分钟微循环

首位新用户必须在三分钟内完成：

```text
看见一个人
→ 走近现场
→ 理解两种以上立场
→ 做出选择
→ 看见人物与空间回应
→ 得到一段可带走的记忆
```

时间目标：

- 30 秒内看到第一位有明确需要的人物。
- 90 秒内做出第一个有代价的选择。
- 180 秒内看到人物、关系或空间的明确变化。

第一轮禁止：

- 强迫用户先阅读完整系统说明。
- 同时展示全部菜单、数值和功能入口。
- 用大量文字代替人物行动。
- 在用户选择前要求理解完整社会模拟规则。

### 4.3 二十分钟一集人生

一集由 3–5 个相互影响的现场组成：

1. 引子：出现一个具体人物和现实困境。
2. 接近：玩家通过地图或跟随抵达现场。
3. 分歧：至少两种立场都有合理动机。
4. 选择：玩家改变一段关系或资源分配。
5. 回响：另一个地点或人物受到影响。
6. 收束：城市生成一句不是评分、而是理解的总结。

每集必须至少包含：

- 一次地图行走或人物跟随。
- 一次真实 3D 室内探索。
- 一次直接人物交流。
- 一次城市级后果。
- 一个可以被未来剧情重新引用的记忆。

### 4.4 长期循环

长期目标不是数值最大化，而是形成一条可被城市识别的个人选择风格。

长期反馈包括：

- 某类人物更愿意接近玩家。
- 特定公共空间逐渐改变用途。
- 过去的选择在新区域产生不同解释。
- 居民引用玩家曾做出的决定。
- 城市以视觉形式积累玩家的关系轨迹。

### 4.5 无界探索的内容结构

无界城不是完全随机城市。内容分为三层：

#### 核心城区

人工设计的主线区域，包含关键人物、核心建筑和首批章节。

#### 主题街区

由审核过的布局语法组合，例如：

- 晨光住宅区。
- 共学与创作街区。
- 公共讨论区。
- 修复与休息庭院。
- 服务与交换市集。
- 记忆与故事街区。

每个主题街区定义：

- 建筑功能集合。
- 路网类型。
- 植被和开放空间比例。
- 人物职业与需求分布。
- 可生成事件类别。
- SkinPack 视觉参数。

#### 稀有地标

按确定性稀有度插入人工设计的地点：

- 镜湖。
- 日光织塔。
- 无人回信站。
- 公共记忆温室。
- 长昼车站。

地标负责提供长期方向、章节入口和视觉记忆点，避免程序化内容趋同。

### 4.6 有趣性门禁

首期试玩验收目标：

- 至少 80% 的首次测试者无需口头帮助完成三分钟微循环，样本不少于 10 人。
- 首个有代价选择的中位时间不超过 90 秒。
- 至少 70% 的测试者完成首个后果后主动进入第二个现场。
- 测试者能够复述“我的选择改变了谁、改变了什么”，而不只是复述按钮文字。
- 任意 20 秒内都应存在可理解的下一步，除非玩家主动停留观察。

## 5. 四套皮肤设计

四套皮肤共享上述玩法，不共享世界表现。

### 5.1 A：温暖绘本城

体验关键词：

- 情感清晰。
- 生活手记。
- 温暖而不幼稚。

美术规则：

- 手绘墨线与柔和水粉块面。
- 建筑轮廓略有不规则，但碰撞和入口保持精确。
- 远景像连续长卷，区块出现表现为翻页和纸面晕染。
- 人物使用美术师制作的完整身体动画帧，不切割完成插画做肢体旋转。

反馈语言：

- 选择以手写批注出现。
- 关系变化成为两个人之间逐渐清晰的墨线。
- 任务完成留下印章、书签或折页。

性能档位：

- 静态区块适合离屏位图缓存。
- 动态效果限制为纸纹、墨迹和少量粒子。
- 四版中性能风险最低。

### 5.2 B：公民纸艺城

体验关键词：

- 社会关系可读。
- 公共讨论。
- 层叠制度空间。

美术规则：

- 建筑、树木和道路由有厚度的纸雕层组成。
- 关系、制度和资源流向通过纸带和节点呈现。
- 区块出现表现为纸张展开、折叠和咬合。
- 不使用廉价剪纸阴影模拟所有深度；重要建筑保留清楚体块。

反馈语言：

- 选择像在公共议题板上放置一张立场卡。
- 社会后果表现为纸带重新连接或断开。
- 任务完成形成社区档案页。

性能档位：

- 纸层阴影预烘焙到资产。
- 实时只保留少数展开和连接动画。
- 性能风险低到中等。

### 5.3 C：温馨微缩城

体验关键词：

- 空间探索。
- 桌上世界。
- 收藏和生活观察。

美术规则：

- 建筑像真实制作的微缩模型。
- 使用陶土、木材、织物和微型灯具的触感。
- 景深只用于静态或低速状态，拖动时关闭。
- 区块出现表现为桌面模型被轻轻放下和点亮。

反馈语言：

- 选择改变房间中的具体陈设。
- 关系变化通过共享物品、座位和灯光体现。
- 任务奖励是可摆放或可观察的微缩生活物件。

性能档位：

- 不在 Canvas 地图使用实时景深。
- 远景建筑合并为静态区块位图。
- 细节密度最高，四版中地图资产成本最高。

### 5.4 D：晴织镜城

体验关键词：

- 正面、明亮、独特。
- 阳光作为叙事材料。
- 关系与可能性被编织进城市。

材料规则：

- 象牙色多孔陶瓷。
- 蜂蜜色木材。
- 染色亚麻。
- 半透明彩色树脂格栅。
- 少量黄铜节点。

禁止：

- 霓虹赛博。
- 全息投影语言。
- 教堂彩窗感。
- 纸艺、黏土或普通玩具城替代材质。

世界规则：

- 每栋建筑拥有 `sunPatternId`。
- 建筑功能决定基础织纹。
- 人物关系决定织纹之间的连接。
- 玩家选择改变光纹的方向、密度和颜色混合。
- 镜像人生不复制第二个人物，只在地面留下另一种可能性的光纹。

区块出现：

1. 远处先出现低频暖色光场。
2. 道路与公共空间沿织纹显现。
3. 建筑从光场中形成清楚轮廓。
4. 只有玩家附近的关键关系光纹进入实时流动。

性能规则：

- 静态光纹烘焙进区块位图。
- 桌面最多 6 个实时光纹源。
- 移动端最多 3 个实时光纹源。
- 拖动时停止高频光纹和模糊效果。
- 远景只保留色带，不绘制细碎织纹。

## 6. 技术架构

### 6.1 选择

采用：

```text
Worker 驱动的 2.5D Canvas 无界地图
  + 按需加载的真实 Three.js / Rapier 室内
  + 共享权威世界状态
  + 可热切换 SkinPack
```

不采用：

- 继续向当前主线程单体脚本叠加全部功能。
- 将地图重写为全 WebGL 无限世界。
- 为四套皮肤复制游戏代码。

### 6.2 模块边界

目标模块：

```text
src/world/
  WorldCoordinates.js
  ChunkScheduler.js
  ChunkGenerator.js
  ChunkEdgeContract.js
  WorldState.js
  WorldDeltaStore.js
  SimulationScheduler.js

src/world-worker/
  world-worker.js
  generate-chunk.js
  analyze-local-graph.js
  rasterize-static-layer.js

src/render/
  WorldCompositor.js
  ViewportCuller.js
  ChunkBitmapCache.js
  ActorLayer.js
  InteractionLayer.js

src/skins/
  SkinRegistry.js
  SkinPack.js
  sunweave/
    tokens.js
    asset-manifest.js
    map-renderer.js
    feedback-renderer.js
    audio-manifest.js

src/interior/
  InteriorGateway.js
  InteriorPrefetchPolicy.js
  InteriorResourceCache.js

src/storage/
  WorldSchema.js
  WorldMigration.js
  WorldExport.js
```

迁移期间 `public/game.js` 保持兼容门面。每次只抽离一个职责，行为等价检查通过后再继续，不做一次性重写。

### 6.3 世界坐标

Canvas 永远保持视口大小。世界位置表示为：

```js
{
  chunkX,
  chunkY,
  localX,
  localY
}
```

区块 ID：

```js
chunkId = `${chunkX},${chunkY}`
```

世界种子：

```js
chunkSeed = hash(worldSeed, generatorVersion, chunkX, chunkY)
```

相同世界版本和坐标必须产生相同基础区块。

### 6.4 区块调度

运行时工作集：

- Active：玩家周围 3×3 详细区块。
- Warm：外围 5×5 元数据、道路入口和静态位图预热。
- Far：仅保留种子、地标索引和社会事件摘要。
- Evicted：删除可重建的渲染资源，保留玩家差量。

缩小地图时不无限增加详细区块。系统切换到宏观 LOD：

- 隐藏人物标签和细节。
- 多栋建筑合成为街区轮廓。
- 道路使用简化主干。
- SkinPack 只绘制低频视觉特征。

### 6.5 无缝边缘契约

相邻区块共享边缘种子：

```js
edgeSeed = hash(
  worldSeed,
  generatorVersion,
  min(chunkA, chunkB),
  max(chunkA, chunkB)
)
```

边缘契约定义：

- 道路出口。
- 水系和绿地连接点。
- 晴织光纹出口。
- 建筑安全边距。
- 人物跨区路径。

生成器不得将所有外围区块通过长道路回连核心城区。核心城区通过邻接区块逐层连接。

### 6.6 Worker

Worker 负责：

- 区块确定性生成。
- 边缘契约。
- 局部道路图。
- 局部空间指标。
- 静态区块绘制。

主线程负责：

- 输入。
- 相机。
- 动态人物。
- 任务反馈。
- 最终 Canvas 合成。

Worker 不可用时：

- 回退到主线程。
- 每帧最多生成一个区块。
- 暂停非必要视觉效果。
- 不阻塞玩家移动和退出操作。

### 6.7 分级模拟

#### 当前区块

- 完整人物动作。
- 碰撞和交互。
- 实时关系反馈。
- 当前任务。

#### 相邻区块

- 低频移动。
- 简化行为决策。
- 不运行完整对话和室内物理。

#### 已访问远端

- 保存人物和社区摘要。
- 重新进入时根据离开时间执行一次有上限的推演。

#### 未访问区块

- 不保存完整内容。
- 不运行模拟。
- 第一次接近时由种子生成。

### 6.8 渲染分层

地图合成顺序：

1. 地形与道路静态位图。
2. 建筑与植被静态位图。
3. SkinPack 环境层。
4. 动态人物。
5. 关系、任务和交互反馈。
6. HUD。

静态内容变化时才重新生成区块位图。

地图人物规则：

- 使用为动画制作的完整身体帧。
- 每位人物每帧尽量只执行一次主体 `drawImage`。
- 禁止把完成插画切成头、手、腿后旋转。
- 缩放和拖动时使用低细节动画。

建筑资产规则：

- 使用真实透明背景。
- 图集单元增加透明间距和边缘扩展。
- 不执行运行时白底抠图。
- 资源未准备完成时显示统一的 SkinPack 占位层。
- 完整资产准备后一次性切换，禁止先画简化建筑再替换造成二次渲染。

### 6.9 SkinPack 接口

```js
{
  id: "sunweave",
  version: 1,
  tokens,
  assetManifest,
  renderStaticChunk(context),
  renderEnvironment(context),
  renderChoiceFeedback(context),
  renderRelationshipFeedback(context),
  getLoadingAppearance(context),
  getAudioCue(event),
  getQualityProfile(deviceProfile)
}
```

SkinPack 必须提供：

- 默认、低质量和无动画档位。
- 色觉无障碍替代符号。
- 缺失资产回退。
- 清理所有位图和音频资源的方法。

### 6.10 真实 3D 室内网关

地图首屏不得加载或初始化：

- Three.js 渲染器。
- Rapier。
- GLTFLoader。
- 目标房间 GLB。
- 公民角色 GLB。
- 室内高分辨率纹理。

预热触发：

- 指针悬停建筑超过 300ms。
- 玩家或跟随人物接近入口。
- 当前任务明确指向目标建筑。
- 浏览器空闲且网络条件允许。

预热顺序：

1. 室内网关模块。
2. Three.js 公共依赖。
3. 目标房间清单。
4. 共享材质和目标 GLB。
5. 进入前准备 Rapier。

弱网、`Save-Data` 或移动端内存压力下，只预取当前目标。

离开室内后：

- 保留短时热缓存。
- 达到内存阈值立即释放纹理、几何和物理世界。
- 共享资产按引用计数释放。
- 事件监听器和动画循环必须可验证清理。

## 7. 存储架构

当前数据库 `mirrorlife` 已有：

- `saves`。
- `memories`，最多 2,000 条。

新版本增加：

- `worldMeta`。
- `worldChunks`。
- `worldEvents`。
- `worldCheckpoints`。

### 7.1 保存内容

每个访问或改变过的区块保存：

- 发现时间。
- 最后模拟时间。
- 建筑变化。
- 居民摘要。
- 重要关系。
- 任务和故事标记。
- 压缩后的事件摘要。

不保存：

- 图片。
- GLB。
- Canvas 位图。
- Three.js 对象。
- 粒子。
- 每帧人物位置。
- 未访问区块完整内容。

### 7.2 容量

- 普通区块：4–20KB。
- 剧情密集区块：20–60KB。
- 1,000 个访问区块：约 5–20MB，剧情密集时约 20–60MB。
- 40MB 开始压缩历史事件。
- 50MB 为默认软上限。
- 100MB 为应用硬上限。
- 同时不得超过浏览器可用配额的 10%。

### 7.3 存档

手动存档保存：

- 世界版本。
- 时间线位置。
- 玩家核心状态。
- 差量检查点引用。

不得为每个存档复制完整世界。

IndexedDB 不可用时：

- 当前会话使用内存存储。
- 明确提示本次探索无法长期保存。
- 提供 JSON 导出。
- 不阻止玩家退出或继续当前现场。

## 9. 备份与回滚门禁

任何网站实现修改前必须完成：

### 9.1 Git

- 记录当前 HEAD。
- 创建并推送只读基线标签。
- 创建并推送备份分支。
- 确认备份分支可以在独立工作树构建。

### 9.2 构建

- 对当前版本执行 `npm run check` 和 `npm run build`。
- 保存生产构建归档。
- 生成 SHA-256 文件清单。
- 在本机解压后启动一次恢复构建。

### 9.3 Vercel

- 记录当前 Production deployment ID 和 URL。
- 新实现只部署 Preview。
- 验收前不提升为 Production。
- 保留上一 Production deployment 的即时回滚入口。

### 9.4 本地数据

- 提供当前 `localStorage` 和 IndexedDB 导出。
- 数据库迁移前生成可下载备份。
- 迁移失败时不删除旧库。
- 使用新版本验证恢复后才允许写入升级标记。

备份门禁必须输出一份包含标签、分支、构建校验值、部署 ID 和恢复结果的报告。

## 10. 错误处理

### 区块生成失败

- 保留最近完整区块。
- 显示 SkinPack 中性的远景光场。
- 重试失败区块，不阻断相机返回。

### SkinPack 资产失败

- 使用几何和颜色占位。
- 不显示另一套完整皮肤，避免视觉闪变。
- 记录缺失资源 ID。

### 室内资源失败

- 保持地图可操作。
- 显示目标建筑仍在准备的明确状态。
- 提供取消和稍后进入。
- 不加载 2D billboard 室内冒充真实 3D。

### 存储失败

- 切换到会话内存。
- 提供导出。
- 保留玩家当前选择。

## 11. 测试与验收

### 11.1 世界

- 相同种子和版本生成相同区块。
- 相邻区块道路、绿地和晴织光纹边缘完全匹配。
- 连续跨越 1,000 个区块后缓存和内存不线性增长。
- 返回旧区块后玩家改变保持一致。
- 缩放到最低档时详细区块数量保持硬上限。

### 11.2 游戏流程

- 新用户三分钟循环。
- 一集人生的 3–5 个现场。
- 选择后局部与远端后果。
- 任务、关系和建筑变化跨皮肤一致。
- 切换皮肤不会重复奖励或重置任务。

### 11.3 视觉

- 建筑没有图集串色和裁剪杂物。
- 地图人物没有重影、残肢和切图接缝。
- 首屏不出现简化建筑后二次替换。
- D 光纹在四向地图移动、缩放和移动端保持连贯。
- 室内进行桌面四向环绕和移动端人工检查。

### 11.4 真实 3D 室内

- `npm run verify:interior-transitions`

- footPlant。
- 袖口和裤口压缩。
- 接地。
- 四向环绕。

### 11.5 发布

## 14. 停止规则

任一阶段连续三次结构性尝试仍无法达到该阶段硬预算时：

1. 停止继续换措辞或微调同一方案。
2. 保留最后一个通过前置门禁的版本。
3. 输出三次尝试的量化差异。
4. 说明受阻的性能、视觉或玩法条件。
5. 请求用户决定缩减范围、追加资源或更换架构。

不得通过放宽预算、删除真实 3D、隐藏失败场景或降低截图质量伪造通过。
