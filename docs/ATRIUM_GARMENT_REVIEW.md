# 人物肩袖续作

本轮修正七名人物的衣身与袖子连接、玩家服装浮起的缝线和口袋。保持现有身份配置、骨架、运行时动作与真实自由移动；没有用固定视角替换模型。整体美术门禁仍未通过。

## 制作与边界

`scripts/atrium-garment.py` 在 Blender 的绑定姿势下将衣身和双袖转为同一米制坐标，执行 7mm 体素合并、平滑和减面，并按原衣身/袖子表面距离向躯干、上臂、肘骨重新赋权。单件上衣不超过 1,700 三角面。构建检查一个连通分量、没有非流形边、权重误差小于 0.0001；结果随 GLB 和 manifest 保存。交付测试检查两档文件携带该审计及合并动作网格的 UV。

这些是实际执行的程序建模与拓扑检查，不是人工四边面重拓扑或人工审核证明。审计只覆盖合并的基础衣身/袖子，不包括全部头发、手指、开衫外层或饰件。林晓、周宁仍有独立开衫外层。上衣使用顶点色，没有布料模拟或新织物位图。

取消玩家和何川的硬块状后领装饰，降低领口和刺绣尺寸。玩家、何川、陈屿的口袋按整个衣服表面采样，缝线贴合胸前曲面。袖根斜面重新构造；各身份肩轴相对原轮廓外移，让下袖与腰身之间留出活动空间。碰撞仍沿用角色胶囊，没有声称实现逐肢体碰墙。

七人桌面 GLB 的唯一网格三角面变化：玩家 -250、林晓 +128、陈屿 +188、许禾 +132、周宁 +128、何川 -251、唐乐 +126，合计 +201。原始资产数与实际逐帧多通道渲染预算是不同口径；实际性能见 `evidence/atrium/PERFORMANCE.md`。

七份 `.blend`、高细节 master、两档运行 GLB 和玩家九段动作参考已同步。动作 GLB 供检查与编辑；运行时仍采样原有同源姿势。UV 增加了资源体积，未为降低体积删除手指或身份差异。

## 证据与五个视角的反对意见

以下是按五种职责进行的自审，不是虚构外部人员审核。完整候选步骤和指纹见 `evidence/atrium/acceptance.json`。人物多角度图见 `garments/report.json`，握持、坐姿、楼梯另有独立实际运行证据；诊断相机不能替代键盘回游。

| 视角 | 可证伪的反对意见 | 检查及边界 |
|---|---|---|
| 玩家/产品 | 衣服变好看，却让交谈和动作失效 | 重新验证坐下、起身、生活动作、三名居民交流、决策与退出重入；首次玩家体验与趣味性仍需用户测试 |
| 关卡 | 扩肩后楼梯与狭窄路线无法连续通过 | 保留原胶囊和路线，用两座楼梯专测及完整键盘回游检查；不等同于全身网格与墙壁无穿透 |
| 美术 | 绑定姿势连成一体，抬臂或侧看仍像拼接块 | 七人正/侧面、玩家背面，加握持和坐姿近景；基础肩袖连通已修，手指、开衫外层、关节褶皱与面部自然度仍不足 |
| 工程性能 | UV 和新拓扑使资源与多通道预算恶化 | 保留上一候选报告，比较资源字节与实测帧时间，继续使用 180 calls / 500,000 triangles / 220 geometries；不以模型面数直接声称帧率改善 |
| QA | 检查只读声明，或用等待时间掩盖动作失败 | Blender 构建实际遍历边和顶点权重；交付测试检查 GLB 审计与 UV。浏览器另测接触和动作。坐姿测试等待实际 seatBlend > .99 后才断言，未放宽误差阈值 |

剩余问题：肩部局部折面和腋下拉伸、开衫与内层衔接、手指抓握与自然表情、正常探索距离的织物层次仍需要精修。世界坐标脚底锁定、完整鞋底穿透检测、真实移动设备、长时间玩家试玩、主世界身份关系双向接入仍未完成。不得把本轮服装修补或资产文件存在解读为原始任务全部交付。

## 本轮实测与目标复核

同一构建的 17 项单元/物理测试、9 个坐立检查点、4 条楼梯方向路线、10 项异常检查及连续回游通过。回游记录 7 项发现、3 名居民交流和 balanced 决策；95.2 秒录像完整解码通过。自动操作跳过人类阅读时间，不是 3–5 分钟真人流程计时。

桌面入口环绕 P95 100.4ms，比上一轮 49.3ms 更差；GPU P95 20.42ms 与上一轮接近，原因尚未查明。移动模拟 P95 17.6ms，不代表真机达标。入口桌面峰值 494,357 三角面，录像回游峰值 485,543 三角面，均保留原预算。性能门禁没有因功能测试通过而被豁免。

北极星复核：本轮没有牺牲连续玩法，衣服连接和贴合有所改善，但美术统一性、角色自然度与稳定帧时间仍不足。下一步优先定位桌面长尾卡顿，同时继续修肩部折面、腋下拉伸与开衫外层，再扩展人物生活演出。

发布为开发分支提交和可运行本机试点，不部署生产站点。提交前保留原用户修改；回退本轮应单独 revert 本轮提交，不能重置用户工作区。尚未开展真实玩家测试，没有编造反馈结论；后续试玩应记录完成率、迷路位置、交互取消原因、实际流程时长和长时间帧时间。
