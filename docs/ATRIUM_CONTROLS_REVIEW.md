# 天井试点 · 穿物、移动镜头与人物反馈修正

## 用户反馈与本轮玩家终点

本轮依据用户实际试玩反馈：人物穿过物体、镜头跟随与前后左右体感不舒服、人物还原度不足。首次玩家应能按画面方向行走，靠近桌椅与植物时被实体阻挡，在窄处仍看得见可走空间，然后完成交流、探索、共同决策和两层回游。

继续沿用 Three.js、Vite、Rapier 和既有剧情/存档边界。整处双层预算仍为 180 draw calls / 500,000 triangles / 220 geometries；不通过删除居民、固定镜头或关闭交互取得指标。本轮不更换主世界或技术架构。

## 已定位原因与修正

1. 原碰撞清单没有共享椅、独立座椅及落地花盆；共享桌矩形碰撞范围也小于可见桌沿。从 Blender 评估后的真实网格提取尺寸，补齐 32 项家具碰撞（含替换共享桌），写回源场景和运行时清单。桌与花盆采用椭圆凸体，椅子使用坐垫与椅背实体范围。玩家胶囊半径从 0.25m 调到 0.30m，保持整体高度；旧存档若落在新增实体内，回到合法入口并保留探索进度。
2. 旧镜头只有五条射线，且只查询简化碰撞清单；看得见的窗框、弧形与装饰厚度可能没有相应阻挡。新镜头复用当前 GLB 已解码的可见几何建立 Rapier 查询索引，略过柔性叶片/土壤，用 0.22m 球体扫掠。它仅参与镜头查询，不作为隐藏的行走障碍。
3. 原相机将整个位置插值，绕墙时容易收近、拉远反复跳动。新实现分别平滑输入角度、跟随中心、镜头距离；碰撞收近立即响应，拉远缓慢恢复，并再次核对最终视线。坐姿观察中心提高到椅背上方。距离过近时人物逐渐透明，避免头部/后背占满画面；模型仍参与渲染统计，不用隐藏人物伪造预算。
4. 原移动直接从静止切到全速，转身使用期望位移，贴墙滑动时朝向可能失配。新增输入死区、归一化、起停缓冲，按实际位移转身；开对话或暂停立即清除移动速度。WASD/摇杆始终相对当前镜头朝向。
5. 原摇杆必须先移动手指才生效，中心也写死为 50px。新实现按实际控件大小计算中心和半径，按下即响应，并处理取消触摸、失去捕获和窗口失焦。

第一次完整回游在西侧椅背被挡住：旧输入路线实际穿过了此前漏碰撞的椅背。保留失败证据 `controls/blocked-old-route.*`，改为走实际外侧通道，二层观景座椅也增加绕行节点。安静区椅子向桌子方向移动 0.30m，扩大回廊净宽，并同步模型、碰撞和地面接触阴影。没有删除家具碰撞来适配脚本。

第一次近距离淡出使用透明混合，截图出现浮眼和穿透头发的排序缺陷（`controls/rejected-transparent-fade.png`），因此否决该效果，改用保留深度的 alpha hash 渐隐。初次性能原始记录单独保留为 `controls/first-pass-performance.json`；最终指标必须取重新测试的候选，不能混用。

## 人物与参考图对照

- 原发束路径中段落在头皮之外，形成悬浮的重复块。本轮沿头皮曲面铺设发束；戴帽居民重新制作带厚度的帽冠、帽檐和贴面徽记，去掉穿帽刘海。
- 降低连续衣身的实际领口，让皮肤颈部可见，并将领边移动到真实领口。唐乐的椭圆鼓包前袋改为贴合衣身曲面的织物口袋。
- 七名角色的可编辑源、master、两档 GLB 与九段动作同步。资产仍为项目原创制作，无付费服务或第三方人物资产。

按最初优先级复核：空间构图仍比参考图松散；主梯/回廊/天窗锚点已存在，窗洞节奏与主梯曲面仍需细化；配色方向保留；光照偏均匀、间接光及材料层次弱；人物头发连接改善，但面部、肩部、手部与衣物变形仍不够自然。没有以“还原度百分比”或几张近景宣称最终美术通过。

## 五视角反对意见

这是同一执行者按五种职责交叉检查，不是虚构独立团队签字。

| 视角 | 可证伪的反对意见 | 回答方式与边界 |
|---|---|---|
| 玩家/产品 | 加惯性可能造成松手滑行；自动避让后看不见前路。 | 测四种镜头朝向的四向输入、触摸取消后的剩余位移、近窗截图和完整录像。手游“舒服”的判断仍需真实试玩反馈。 |
| 关卡设计 | 新椅子和花盆碰撞会堵死交谈、桌边决策或两条回游路线。 | 持续顶家具测试、完整物理回游、真实键鼠决策/两层录像；同时检查坐下起身和居民站起通道。 |
| 美术 | 只是补碰撞和缩小几何，人物仍不接近参考。 | 本轮实际重做发束、帽子、领口和口袋，并检查七人正侧面。面部光影和完整服装动画仍未达到参考品质，保留这项反对意见。 |
| 工程性能 | 给镜头复制可见三角面会增加加载、WASM 内存和每帧查询成本。 | 索引只构建一次、复用已加载资源；在同候选实测初始化耗时、帧时间和 JS heap。没有获取 WASM/进程总内存，不将 JS heap 作为总内存。原渲染预算不变。 |
| QA | 自动测试只证明胶囊没穿桌，不证明所有动画肢体都不会穿模。 | 明确区别胶囊通行、可见几何镜头扫掠、手脚接触和自然动画。家具阻挡通过不等于全部手指/衣袖穿模已消除。 |

## 复现和交付入口

- 运行：`http://127.0.0.1:4193/atrium.html`；WASD、拖动、滚轮、E，手机左摇杆/右侧拖动。
- 完整验收：`npm run verify:atrium:release`；专测：`node scripts/verify-atrium-controls.mjs`。
- 方向/家具/双指原始记录：`evidence/atrium/controls/report.json`；近窗与家具截图在同目录。
- 人物对照：`evidence/atrium/faces/review.html`，七人视图在 `garments/`。待机相位未锁定。
- 碰撞重建：Blender 运行 `scripts/repair-atrium-furniture-collision.py`；它读取评估后的实际源网格，重复执行替换同一批结果。
- 独立性能与录像以本候选 `acceptance.json`、`PERFORMANCE.md`、`video-validation.json` 为准。

正式手机硬件、长时稳定性、完整主世界身份/关系双向集成、自然表情与最终美术仍待完成。屏幕/触摸模拟不是手机实机验收。

## 当前候选视觉复查

运行截图已检查校准视角、玩家正面、何川正面、回游楼梯近窗与双指操作画面。近窗不再出现透明混合造成的浮眼，但侧向镜头仍可能只能看到近墙，地面信息不足；alpha hash 在淡出过渡中会有颗粒。七人近景仍暴露方肩、手部棱角及局部袖口异常，移动端任务面板也占用较多画面。以上不能因专项自动检查通过而视为解决。

最终独立采样中，桌面 P50/P95/P99 为 16.7/17.7/34ms；移动模拟为 16.7/17.7/200ms。移动 P99 的长帧是尚未解释的性能风险，不能只按 P95 宣称流畅。完整指标和候选指纹由 `PERFORMANCE.md` 与 `acceptance.json` 记录。

2026-09-11 最终候选 `95237cf2c7ac1780d82826162762fc444e1e4b2fab157317cf9b0606a4f5669b` 的 17 个验收步骤执行成功：19 项单元/物理回归、构建、多视角、两档独立性能采样、人物/操作/接触/坐姿/楼梯/异常专项、完整回游与视频解码、前后指纹核对和报告生成。这里的“执行成功”不代表美术和帧率门槛全部通过。

真实键鼠路线通过 40 个路点，完成 7 项发现、3 位居民交流、balanced 共同决策及退出重入。连续录像 97.67 秒、1465 帧，完整解码成功；已检查八张均匀时间抽帧与 93 秒近尾帧，画幅连续且能看到一层、主梯、二层与回游梯。抽帧不是逐帧视觉验收，自动快速选择也不是人类 3–5 分钟体验证明。近墙楼梯画面仍偏局促。录像 SHA-256 见 `video-validation.json`。
