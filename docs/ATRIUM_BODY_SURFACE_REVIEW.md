# 蒙皮衣身、手部与鞋面 · 续作

本轮解决原始材质在蒙皮合批中丢失的问题。它改善表面响应，不能代替人物造型重做或证明参考图还原度达标。

## 玩家目标与设计约束

首次玩家沿入口接近居民、转动视角观察、交流并完成共同决策；服装和皮肤应在这些正常距离下有区别。仍沿用既有入口提示、交互反馈和决策记录。保持人物身份、连续移动、骨架、手部锚点和碰撞；不改变玩家下一步操作，不加入等待流程。

保留双层整体 180 draw calls / 500,000 rendered triangles / 220 geometries 预算。主画面加动态阴影按实际帧统计，不按单一资产面数推算。失败信号为人物变透明、材质闪烁、合批增加、手部动作或设施接触退化。

## 原因与制作

上一版刚性头脸等部件已保留四类材质，但 `SkinnedArticulationCore` 仍统一使用 .68 粗糙度。共享构建器原本只复制各部分颜色，丢弃了布料 .91、皮肤 .74、鞋面 .68 等原始表面响应。

本项目的居民构建脚本在合批前临时携带原始粗糙度，合批后转换为第二套 UV 和 256×1 线性粗糙度查找贴图，并恢复完全不透明的顶点颜色。使用标准 glTF metallicRoughnessTexture，绿色通道、texCoord 1；没有运行时自定义着色器。第一套可编辑 UV 保留，蒙皮身体仍为一个 primitive。贴图打包在可编辑 Blender 源和 GLB 内，无外部纹理下载依赖。

七名居民两档资产及主角九段动作同步导出。新增内容均为项目原创，无第三方服务或新增许可。共享 civic 构建器未修改。

## 五视角反对意见

| 视角 | 可证伪的反对意见 | 回答与边界 |
| --- | --- | --- |
| 玩家/产品 | 正常距离看不出改变，无法解决人物还原不足 | 同镜头前后图显示衣身高光收敛，但整体改善有限；不能将本轮称为人物验收完成 |
| 游戏设计 | 导出调整破坏动作、掌心锚点或通行 | 保留骨架与权重，资产检查及完整路线检查仍为必要门槛 |

| 工程性能 | 分材质造成批次膨胀或资源增长 | 身体仍一批次；每个桌面 GLB 增加 556–940 字节，移动 GLB 增加 680–856 字节；实际性能另测 |

## 比较与验证范围

`evidence/atrium/faces/review.html` 左侧为 d9f02c1 的玩家 GLB，右侧为新 GLB；同一运行场景、相机与画幅。真实待机和眨眼未冻结，不进行像素差分归因。此对照不是参考图校准；参考场景比较仍见总证据页。

初次资产测试错误地假设 UV accessor 一定带 min/max，以及全不透明颜色一定导出 VEC4；实际 glTF 两者都可省略。检查改为读取 master UV 二进制，允许 VEC3；VEC4 时逐顶点核对 alpha=1，未放宽材质数据要求。22 项单元/资产测试已通过。

最终同构建运行指标与录像见 `evidence/atrium/acceptance.json`、`PERFORMANCE.md` 和 `playthrough.json`。最终运行结果见下方。

当前一层运行图仍暴露出整体差距：主楼梯侧墙占据画面过多，建筑曲面缺少参考图的连续过渡，窗景和植被层次稀薄，人物肩部与脸部仍显生硬。此次不把保留材质数据当成上述问题的解决证据。

近墙残余限制：四处推挤虽然胶囊均未穿透，但在极窄窗角，镜头仍会收缩至约 0.08m 并将人物完全淡出。这是既有避让策略的体验折衷，不能视为第三人称手感已最终通过。本轮只回归此行为，没有修改镜头策略。

## 异常检查与补验

初次同候选验收完成至两梯检查，随后居民忙碌用例失败：脚本在任意 busy=true 时刻继续发键，断言对话关闭失败。旧测试没有记录按键瞬间状态，不能断言一定是运行时错误或一定是时间边界。代码显示许禾忙碌为每 18 秒的前 3 秒，原等待确实允许在忙碌末帧返回。

修正测试为等待一次空闲→忙碌的新周期，并在真实 keydown 捕获阶段记录居民状态和提示；仍严格断言按键发生时 busy=true、对话未开、提示稍等，随后自然恢复可对话。不冻结游戏时钟、不伪造居民状态。保留初次失败于 `resilience-initial-body-surface.json` 及对应 validation 日志。

补验先核对运行指纹和所有 public/dist 资产 SHA-256，再重跑异常流程及后续录像。前 13 个通过步骤的时长未恢复，在最终 JSON 中明确记为 null；不把补验伪装为一轮全新完整执行。常规复现仍使用 `scripts/verify-atrium-release.mjs`。


补验的 10 项异常路径通过，实际 keydown 捕获到许禾 busy=true，提示为“和许禾聊聊”；随后忙碌提示与恢复对话断言均通过。

首段录像在二层坐下前失败。实测终点 (9.480, 5.456) 到座椅热点 (9.4, 5.25) 的距离约 .221m，到观景热点 (9.35, 5.6) 约 .194m，故画面提示“从楼上看看”符合现有最近点规则。原路径目标 z=5.35 及 .2m 到达容差跨过两热点分界。第一次尝试接近点 z=5.2，但真实椅子碰撞在 z≈5.405 停住玩家，无法达到原容差，测试正确报阻塞。最终使用 z=5.3，并要求距离条件和画面“落座”提示同时成立才结束接近；仍由真实按键前进，椅子保持实体碰撞，不放宽容差。初次轨迹与截图保存为 `walkthrough-initial-body-surface.*`。相邻热点的辨识和切换体验仍可改善，此修正不等于改进了产品交互选择。

第二次接近失败轨迹及日志保存在 `walkthrough-seat-approach-body-surface.json` 和 validation 对应文件；原失败未删除。


## 最终同候选结果

运行指纹 `dae18bfc96db4ed8e3a7e4efc63c5ba3ff06bb03132d4ed37b4f9206f591343a`。22 项单元/资产测试、21 项操作检查、4 处窗墙推挤、设施接触、坐姿、两座楼梯及 10 项异常流程通过。完整按键路线最终完成 40 个节点（保存的退出前轨迹含 39 个，退出为第 40 个），七项发现、三位居民、balanced 决策和退出重入状态验证通过。

桌面本机 Chrome 152 / AMD Radeon Pro 5300M / 1920×1080 DPR1，P50/P95/P99 为 16.7/17.5/17.7ms，峰值 116 calls / 495,996 triangles / 92 geometries，导航至就绪 3324.1ms。移动为同桌面 GPU 的视口/触摸模拟，P50/P95/P99 16.7/17.5/17.7ms，94 / 311,550 / 88。两档渲染预算通过；桌面严格 60fps 门槛未通过，模拟 30fps 门槛通过不代表真机认证。
