# 裤侧细节、窄梯稳定视野与玻璃遮光

本轮继续面向首次玩家：近距离看人物时没有悬空装饰，窄梯停步后能看清自己和踏步，然后继续交流、探索、决策和回游。技术架构、身份、碰撞及双层预算不变：180 calls / 500,000 triangles / 220 geometries。

## 修改与证据边界

旧 `HipLoadFold` 是独立褶皱薄片，没有贴合试点裤型。本轮移除这两条悬空薄片，在连续裤体表面制作最大 2.5mm 的浅折痕；保留裤体、四肢、手指及握持点。七名角色的 Blender 源、master、两档 GLB 与玩家动作源同步，均为项目原创制作。

窄梯原镜头搜索最高俯角不足，可用距离约 1.11m，使人物长期停在约 0.57 的透明度。提高受阻搜索的俯角上限至 1.4 rad，并以 1.5m 为目标安全距离；仍对每个候选扫掠，顶棚无改善时不强抬镜头，左右朝向不变。新增稳定后透明度 > 0.99 的真实窄梯检查，同时保留 250ms 过渡截图和等待 1.2 秒后的截图。这个特定开放顶部案例不再持续颗粒化；其他无空间区域和过渡仍可能淡出，不能宣称所有渐隐颗粒已解决。

运行时玻璃材质 alpha 为 0.09，却被统一设置 castShadow。当前 Three.js 阴影实现不按该透明度透光；本轮只让 `Window glass` 不投实体阴影，墙体和窗框照常投影。不是烘焙 GI，也没有实现物理彩色透射。校准视角变化有限，整体光照仍偏平；保留修改前图，不夸大改善。

## 五视角反对意见

| 视角 | 可证伪的反对意见与验证 |
|---|---|
| 玩家 | 更高俯角可能失去方向感。保持 yaw，窄梯稳定图确认踏步和完整人物；完整键鼠回游另测。舒适度仍需真实试玩。 |
| 关卡 | 抬高可能穿楼板。每次探测受原球体碰撞约束，顶棚单元反例、楼梯专项及两层回游同时检查。 |
| 美术 | 移除薄片只让裤子更简单。折痕移入真实表面，七人正侧面检查；裤型与布料层次仍简化，不称成品。 |
| 工程 | 探测范围扩大增加 CPU，透光改变明暗。最终同候选采样，预算不提高；玻璃改动不增加阴影通道。 |
| QA | 稳定截图掩盖过渡问题。两种时刻都保存，自动用例不等于逐帧视觉或手机实机验收。 |

## 当前验收与性能反例

同候选 `9e7f70b736cc894e0c25346e3fefc8955b2f0bd7a6abe4830739cac1cc8b3c47` 的 17 步流程执行成功，包含 20 项回归、21 个操作用例、7 项发现、3 位居民交流、共同决策、两层回游及退出重入。窄梯稳定距离约 1.526m、俯角约 1.17rad，透明度恢复到 1。录像 117.2 秒 / 1758 帧，完整解码成功；抽帧检查不等于逐帧人工验收。

首次桌面 P50/P95/P99 为 16.7/33.5/82.5ms，峰值 86 calls / 495,235 triangles / 76 geometries。移动模拟为 16.7/17.4/17.7ms，70 / 311,115 / 72。渲染预算通过，但桌面性能退化且未通过帧率门槛。一次同构建生产预览复测仍为 16.7/33.3/49.3ms，记录在 `controls/desktop-repeat-surface.json`；主验收保留首次数据，没有替换为较好结果。

诊断时观察到系统合成及其他进程较高 CPU 占用，但这不能证明退化完全来自外部负载。随后同资产 dev-server 开关对照按旧/新/新/旧次序采样，P95 为 17.5/49.9/49.9/49.8ms，GPU P50 为 9.17/24.90/26.10/21.10ms，渲染峰值相同。最后旧行为也变慢，说明运行顺序/主机波动是重要混杂因素；仍不能排除本轮改动的成本。原始记录 `controls/surface-cost-ab.json`，复现脚本 `scripts/diagnose-atrium-surface-cost.mjs`。开发服务器诊断不是生产验收；目前性能根因未定位，不能发布为稳定 60fps 成品。
