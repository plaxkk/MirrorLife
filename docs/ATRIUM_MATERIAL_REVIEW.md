# 人物材质分离与慢帧复查

继续面向进入生活馆、走近居民并完成交流的玩家。本轮优先避免把帧率波动误诊为镜头问题，并让近距离人物表面保留区别。玩法、碰撞、两层回游和 180 calls / 500,000 triangles / 220 geometries 预算不变。

## 发现与修改

原人物导出在刚性控制节点下统一合并为粗糙度 .78 的材质，抹平源文件中的头发、皮肤、眼睛与服装响应。本轮按控制节点和四类表面分组，保留顶点颜色；粗糙度分别为皮肤 .74、头发 .63、眼睛 .43、服装 .91。没有用重新着色的截图替代模型。新增交付检查验证两档七人 GLB 实际使用这些不同材质，并保留骨架。

这只修正原先被统一的刚性表面。连续蒙皮衣身、四肢和手仍使用已有合并材质，尚未获得逐区域材质遮罩；不把本轮描述成全身材质已完成。鼻梁、鼻尖的局部几何起伏同步增强，继续从连续脸部表面长出，保留可编辑源和正侧面比较。肩部和面部设计、布料织纹、完整表情仍未达到参考品质。

## 性能反例

在修改资产前，以 `2feed80` 的同一运行场景做 GPU 计时开启/关闭/关闭/开启交替采样，真实可见 Chrome、1920×1080、DPR 1，六段拖动加等待，分别超过 30 秒。P95 为 17.5 / 17.3 / 32.5 / 33.4ms。后两轮关闭与开启都慢，不能支持“关闭计时器便能解决慢帧”的假设，因此保留原计时能力，未把较好一轮替换正式报告。

原始数据：`evidence/atrium/controls/timer-overhead.json`；复现：`node scripts/profile-atrium-timing-overhead.mjs`。这是开发预览诊断，不能替代生产候选、真实手机或长期稳定性验收。尚未定位慢帧根因。2026-09-11 17:17 的只读系统查询未记录 thermal/performance warning，CPU Scheduler/Speed Limit 均为 100；这不是 GPU 温度或频率测量，不能据此排除 GPU 限制或证明外部负载原因。

## 五视角交叉检查

| 视角 | 可证伪反对意见 | 验证与边界 |
|---|---|---|
| 玩家/产品 | 增加人物细节却让靠近交流更慢 | 最终候选重测桌面/移动模拟与完整交流路线；性能门槛按真实数据，未通过就保留未通过 |
| 游戏设计 | 改分组丢失眨眼、口型或对话动作 | 保留原控制父节点、骨架及身份，动作/坐姿/完整流程回归检查 |
| 美术 | 材质不同仍没有自然人物感 | 同镜头正侧面对照；当前差距包括弱表情、肩型和全身布料，局部响应不能代替造型验收 |
| 工程 | 多材质会增加 draw calls 和几何对象 | 不提高预算，记录实际峰值；LOD 仍按原比例、头部族使用同一保留率 |
| QA | 只保存材质名字但未在 GLB 使用 | 新测试遍历实际 primitive 的材质引用及 roughness；截图仍需独立视觉判断 |

来源为项目原创 Blender 角色及既有 civic 骨架，无新增外部资产、费用或许可。

## 录像交付

上一轮录像略超 GitHub 建议的单文件 50MB。保留实时轻量编码，在实际输入录制结束后再做 H.264 medium / CRF22 压缩，原帧序列、时间戳和画幅不变；不在游玩时争抢编码 CPU。完整解码检查另外核对实际时间轴与帧数。压缩是交付体积优化，不是游戏帧率改善；有损编码仍需检查文字和动作画面。

## 本轮同构建性能

桌面短测 P50/P95/P99 为 16.7/17.5/17.7ms，峰值 116 calls / 495,996 triangles / 92 geometries；移动模拟为 16.7/17.5/17.7ms，94 / 311,549 / 88。两档都在原渲染预算内；桌面严格 P95 ≤16.67ms 门槛仍未通过，移动模拟 P95 ≤33.33ms 通过。不能把模拟结果当成手机认证，也不能把本次比上一轮平稳解释为材质修改提高了帧率。

人物刚性批次由每人 7 个网格变为 10–11 个（包括口型切换部件）；使用五种材质，其中四种为新保留的表面族，一种为原蒙皮合并材质。七人桌面资产三角面总数基本不变。主画面与阴影的实际提交仍以 renderer.info 峰值为准，不把资产面数当作帧内成本。

初次完整验收已执行到异常恢复并走完 40 个路线节点，但把二次压缩放在 recorder.stop 内触发了既有 20 秒收尾期限。已撤回该位置的改动，把压缩移动到浏览器关闭后的独立视频验证阶段，保留 20 秒采集收尾期限；没有放宽游玩测试。

补验先核对原候选运行指纹、每项 dist/public 资产 SHA-256，再重新录制完整回游并验证视频。前 14 个已完成步骤的时长没有恢复，最终记录将其记为 null，并明确区分原运行和补验；不编造一轮全新的连续验收时长。正常复现仍运行 `scripts/verify-atrium-release.mjs`。
