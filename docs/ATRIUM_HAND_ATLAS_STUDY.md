# 手部图集隔离与颜色修正

## 目标与裁决

上一轮分指改善了轮廓，但身体混合图集在手部产生黑色三角斑，通用背景扩展又引入衣料串色。本轮为探索、交谈和环绕近景中的手部消除这一可见缺陷，保留分指、真实三维和既有控制结构，不以关闭阴影或纯色诊断材质作为运行效果。七人生产美术目标、核心玩法及原性能预算不变。

**第二版保留进入接入准备，尚未替换正式资产。** 正常材质的交谈和抬手左腕近景中，原黑斑与蓝/浅色污染消失。双档实际解码采样通过；但掌指比例和硬折面仍需精修，持物接触、完整动作、真机与性能验收没有完成。

## 实现

`ATRIUM_HAND_ATLAS_STUDY=1` 仅作用于身体合并网格，输出限制在 tmp。以实际手骨权重筛选手部面；对源颜色域正确区分 POINT 与 CORNER，并断言每手颜色和粗糙度均一致、粗糙度处于非布料微表面范围，拒绝把未来非均匀手部材质压成常色。

左右手各保留一块图集区域。原手部 UV 经仿射变换进入 U=.016–.048，各自位于不同 V 半区；填色区为 U=0–.064，保留过滤边距。其余身体 UV 转为 U=.08–1，横向分辨率损失约 8%，未增加贴图分辨率。手部写入源颜色、源粗糙度及中性切线法线，不使用邻近衣料推算肤色，不增加材质或绘制单元。

源顶点色为线性值，DIFFUSE 图像填入 sRGB 编码值；粗糙度和法线保持非颜色数据。此规则由实际导出像素检查验证，不靠代码推测。

## 失败与证据

证据位于 `evidence/atrium/hand-atlas-study/`：

- 首次生成把 POINT 域顶点色当成面角索引，统一颜色断言失败；已纠正，原日志保留为 `initial-point-color-failure.log`。没有放宽统一颜色条件。
- v1 消除了暗斑，但漏了 sRGB 编码，手明显变深。`v1-runtime.json` 明确为失败，最大颜色差 .274514；图像保留在 `v1-mobile/`。没有改变采样阈值来迁就错误。
- `v2-runtime.json`：实际 GLTFLoader 解码两档，左/右手各 906/918 个导出顶点，每档合计 21,888 个基础纹理层的 2×2 过滤邻域检查；肤色、粗糙度 G 通道及法线最大误差 .001961（8 位量化范围），手和衣料 UV 越界均为零。检查不覆盖远距离 mip 或所有纹素。
- `v2-mobile/`：四组肩肘腕姿态、三向及跟随左手的近景，正常材质与阴影；已查看交谈和抬手左腕，未见原黑斑或串色。移动为桌面 GPU 视口模拟，不是实体手机。
- `v2-desktop/`：与 hand-digits-v1 同镜头对照全身、衣装正侧背，以及真实 W 键行走三帧。页面 errors 为空，移动位置断言通过。人工查看衣装正面前后和候选行走，未见明显衣料清晰度退化；非锁相对照，也未量化远距离 mip 清晰度。
- `v2-geometry.json`：对全部网格逐项复核规范化顶点和有向面多重集，一致；报告列出的不同仅是存储顺序。不是材质、UV、形态键或控制全量比较。
- 双档基础纹理 UV 检查、Python 语法、JavaScript 语法和 diff 检查通过。

`v2-resources.json`：桌面 2,279,676 B / 26,404 三角面；移动 903,628 B / 24,341 三角面。相比 hand-digits-v1 减少 138,404/56,032 B，面数不变；两者均 6 材质、7 个网格绘制单元。不据此宣称实际帧时间改善或全场景预算达标。

## 五视角自审

| 视角 | 质疑与结论 |
| --- | --- |
| 玩家/产品 | 去除暗斑后是否更可信？近景缺陷已改善，正常行走画幅没有明显新伪影；整体手形仍不够自然。 |
| 游戏设计 | 是否影响抬手和交谈动作？候选四组实际骨架姿态已检查；本轮没有新的完整对话或握持验证。 |
| 美术 | 单色区域会不会抹掉已制作细节？源颜色/粗糙度一致性断言通过，当前手部本就没有非均匀材质；以后新增指甲、肤色变化须换专用烘焙，不能放宽断言。 |
| 工程性能 | 给手部分区是否降低衣装清晰度？牺牲 8% 横向 UV 空间，近景和行走未见明显退化，但远 mip 和真实弱设备尚待检验。 |
| QA/发布 | 源验证通过是否保证导出颜色正确？首版实际采样抓出 sRGB 错误，修正版保留相同阈值通过。最强反对意见是当前只证明基础层采样，不足以放行所有距离和发布。 |
