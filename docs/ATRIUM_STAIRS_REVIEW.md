# 天井生活馆 · 楼梯脚底接触续作

## 玩家目标与设计

首次玩家沿右侧楼梯寻找楼上居民，再从西侧回到共享桌。玩家应能连续上、下楼和停步，脚底高度跟随实际台阶，动作变化不阻断移动。保留入口提示、探索记录、对话与共同决策循环；无需新增操作或等待界面。首次 30 秒仍由原入口引导，首次 5 分钟仍为既有探索—交流—共同选择流程。

本轮解决原楼梯动画只增加固定膝角、未读取地面高度的问题。玩家能感知的改善是台阶上的腿部弯曲和鞋底落点。目标不是以数值接触代替完整步态、美术或原始任务验收。预算仍为双层合计 180 calls / 500,000 triangles / 220 geometries，桌面原生 1080p 60fps、移动模拟 30fps；不提高预算。

## 实现与来源

- 复用 Rapier 现有台阶实体。每只脚探测脚心、脚尖和脚跟三个位置，向下读取水平承托面；排除玩家和居民胶囊，拒绝墙体侧面与缺失地面。
- 基于现有玩家骨架的真实大小腿长度求两段腿角，鞋子反向转动保持水平。支撑半周期落向地面，摆动半周期保留抬脚弧线。
- 髋部降低以覆盖高低台阶的伸展距离，降低幅度限制为 28cm，抬回采用阻尼。髋部和无台阶脚保留过渡混合，已探测到台阶的脚使用完整接触约束，避免初始混合把鞋底拉回踏面内部；坐姿期间退出楼梯解算，沿用上一轮坐姿约束。
- 保留可达性误差、混合权重、探测面名称和脚底估算指标；缺少地面时恢复原动作，不移动物理胶囊来伪造接触。
- 来源为本项目原创运行时代码 `src/atrium-stair-pose.js` 与既有原创角色资产，没有新增付费或第三方资产。动态约束读取任意当下台阶，不能烘焙成脱离地形的固定动作 GLB；原 Blender/GLB 动作参考保留，编辑运行时解算需修改上述源码。

## 五视角反方审查

| 视角 | 可证伪的反对意见 | 证据与裁决 |
|---|---|---|

| 关卡 | 只在主楼梯正面有效，回程方向或平台无法衔接 | 四方向专测与原完整回游，楼梯专测起点夹具明确标注。斜走、快跑和楼梯原地转身仍缺全面样本。 |
| 美术 | 数学鞋底正确，却脚滑、服装破损，不能算自然步态 | 接受最强反对意见：本轮解决高度接触；脚底尚未世界坐标锁定，衣服和肩部仍明显简化。停步近景、回游录像及逐帧指标同时保留，整体美术门禁未通过。 |
| 工程性能 | 六次射线与关节解算增加每帧开销 | 仅玩家执行该地形约束，复用物理世界，无新增网格/材质/绘制通道；正式构建顺序重测桌面/移动模拟，原始性能保留。没有固定条件 A/B，不能量化解算单项开销。 |
| QA | 只抽最好的稳定帧，隐藏进入楼梯时的错位或回归坐姿 | 报告分别记录充分混合支撑帧和过渡支撑帧；停步两脚均检查。复验坐姿、握持、异常与完整共同决策流程。指标是骨骼脚底偏移，不是完整网格碰撞证明。 |

## 验收与残余风险

`npm run verify:atrium:release` 已加入 `verify-atrium-stairs.mjs`。当前同构建结果见 `evidence/atrium/acceptance.json`；楼梯指标及四幅近景在 `evidence/atrium/stairs/`。完整输入录像在 `evidence/atrium/playthrough.mp4`。性能数值与设备条件见 `evidence/atrium/PERFORMANCE.md`，保留上一轮 `PERFORMANCE-before-stairs.md`。

首轮正式候选的过渡帧发现约 4.4cm 估算下陷，已拒绝该候选。原始反例保存在 `evidence/atrium/stairs-before-contact-fix.json`。原因是完整脚底约束又混回了未贴地姿势；修正为台阶接触优先，并给过渡帧加入独立失败门槛。

最终正式候选四条路径共记录 1,196 个充分混合支撑脚样本，最大估算高度差约 1.91mm；31 个过渡支撑脚样本中，最大向上偏移约 12.95mm，未再出现首轮的向下 4.4cm 问题。该精度仅描述骨骼估算，不能外推完整鞋子网格接触精度。

楼梯专测在每个梯口设置起点，仅该起点使用位置夹具，随后全部以按键行走，不把它冒充完整入场路径。完整回游录像独立从入口开始、不传送。首轮录像还在接近林晓时卡住（`walkthrough-before-heading-fix.json`）。复查发现回游脚本假定鼠标环绕后镜头精确回到零角度，却按世界坐标直接选择镜头相对的 WASD；本轮改为只读当前朝向，将路线误差转换到玩家实际输入轴，并在轨迹记录朝向。保留真实鼠标环绕，不调用设置朝向或传送来修正完整路线。随后复测排除了“只修正朝向即可”的假设：录像又在桌侧通道停止。独立 Rapier 复现使用记录的镜头角 1.236064453125，旧二值方向选择 600 轮仍停在约 [4.205, 0.020, -0.555]；改为每轴 45cm 的短距离纠偏后，37 轮到达约 [3.039, 0.021, 5.541]。旧脚本以远处目标直接选择等强度 WASD，跨线误差累积后撞向楼梯侧墙；该结果不需要浏览器即可重复。最终验收控制使用镜头相对方向、短距离纠偏和真实键盘重复事件，并记录焦点变化。该修正针对验收控制逻辑，不能用来宣称玩家碰撞系统因此得到改善。

数学约束测试还覆盖前后目标、不可达目标、排除居民和墙体探测。

骨骼鞋底高度误差与真实鞋子体积是不同指标。需要继续做鞋底顶点/碰撞包络校验、世界坐标支撑脚锁定、斜走/快跑/转身审查，以及人物肩部与衣服精修。空间比例、圆角轮廓、层次光照与参考图仍存在明显差距。桌面稳定 60fps、真实手机、长时试玩和生产环境尚未通过；不宣布原始任务完成。

## 发布与目标复核

必要检查通过后按项目规则提交并推送开发分支，不代表生产发布。变更不修改存档格式；可通过正常 revert 撤销本轮代码，不清理玩家存档。没有真人反馈或上线转化数据，不能编造体验改善幅度。后续观测重点为楼梯动作可信度、楼梯转向舒适度及真实帧时间。

当前更接近“可连续探索且空间可信”的目标，但仅靠高度解算仍不足以获得精品人物动作。下一轮优先处理人物肩部/衣服、支撑脚滑动和已实测的桌面渲染成本；性能改动需要保持人物身份、完整建筑和自由镜头，并做固定条件 A/B。

最终验收汇总：17 项试点测试、四角度录制导航物理回归（包含在 17 项中）、四条楼梯接触路径、坐姿/握持/异常用例通过。最后回游记录 33 个离开前路线点，另以真实交互离开并重入确认存档；7 项发现、3 位居民与 balanced 决策保留。连续录像为 93.07 秒、1280×720、15fps，已完整解码。验收记录明确保留整套命令中途失败及同构建脚本修正后的专测重跑，不伪称首次命令全通过。

录像抽帧还发现可见 Chrome 原生窗口尺寸变化导致画面缩在左上角（反例 `recording-before-layout-fix.png`）。短录制验证 headless 本机 Chrome 的 1920×1080 页面与画布尺寸完整，且仍使用 AMD / ANGLE Metal GPU 后，最终录像改用该模式；全流程检查画布尺寸。它是实际 WebGL 场景和实际输入记录，不是合成视频；可见 Chrome 的性能/美术证据独立保留。
