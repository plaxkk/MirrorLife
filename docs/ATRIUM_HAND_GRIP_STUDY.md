# 可编辑握姿与拿放过渡候选

## 目标与当前裁决

上一轮端杯俯视证实张掌持物。本轮面向探索、浇水和泡茶玩家，制作随动作收拢、完成后张开的真实网格握姿；保留三维移动、环绕和已有活动结果。全七人高标准还原目标与性能预算不变。

**动作驱动通路已验证，持物美术仍未通过，候选不安装。** 反向近景可见四指发生弯曲，但仍未形成可信的杯柄包握，拇指、指根与把手位置需要按实际几何调整。不能把权重接近 1 或锚点重合称作接触完成。

## 实现

`scripts/atrium-hand-grip.py` 在合并身体的右手上制作 `GripRight` 形态键。指根以外采用连续圆弧弯曲并旋转截面，拇指外缘向内收；Basis 保持中立。它是可编辑握姿原型，尚不是分指关节骨架，也没有碰撞求解。只允许 `ATRIUM_HAND_GRIP_STUDY=1` 输出到 tmp；在手形、分指、短袖口和手图集候选上构建。

运行端仅对含该形态键的网格响应照料状态，用指数阻尼收拢/释放。正式已安装资产没有此形态键，继续使用原手势；运行代码已改变，因此旧运行指纹不代表本轮源码。证据中的 `runtime-modules.json` 保存实际两个修改模块的 SHA256。

## 证据与限制

位于 `evidence/atrium/hand-grip-study/`：

- `v1-source.json`：324 个顶点变化，全部属于完整右手权重组，默认形态权重为 0，最大位移 .052391。没有证明自碰撞或解剖质量。源 SHA256 为 `58f4021ddc12fd334e356e02cfaaf0970620c7ace6b7e67c7beafbe82229c981`。
- `v1-contact/`：桌面实际 E 键触发两种照料动作，六个持物视角收拢权重均大于 .9996，自然完成后降到约 2.27e-7。30 个有效握点样本误差最大约 2.22e-15 米，无页面错误。夹具直接定位，不证明完整探索旅程；释放截图手部偏离近景中心，仅以权重检查证明恢复状态。
- `v1-mobile/`：实际请求并解码移动 GLB，一次候选请求；同样收拢/释放断言通过，释放约 1.26e-7，25 个握点样本。移动是 Chrome 视口模拟且用键盘触发，不是真机或触控交互验收。已查看移动杯柄反向近景，包握问题仍存在。
- `v1-atlas.json`：两档实际纹理采样通过，图集隔离无越界；仅基础层纹理邻域，不证明远 mip 和形变后全部表面质量。
- `v1-resources.json`：桌面 2,476,616 B / 26,404 面，移动 1,092,480 B / 24,341 面；均 6 材质、7 绘制单元。相比 hand-form-v1 分别增加 191,220 / 191,224 B。面数不增，但身体整网格形态数据有明显成本，未测实际帧时或 GPU 内存。
- `regression.txt`：28 项相关回归通过；针对已安装资产的断言不能替代候选资产验收。`build.txt` 构建成功，仍有大 chunk 提示。Python/JavaScript 语法和 diff 检查通过。

## 五视角复核

| 视角 | 可证伪质疑与裁决 |
| --- | --- |
| 玩家/产品 | 手开始弯曲是否就更可信？反向与俯视仍显松散，动作通路进展成立，生产美术不放行。 |
| 游戏设计 | 完成活动会否遗留握拳？桌面/移动实际活动自然结束后权重回到近零；取消/重复触发还未完整覆盖。 |
| 美术 | 通用圆弧是否适合杯柄和水壶两种握法？当前未包握，需按把手几何逐指设计，不能只继续提高权重。 |
| 工程性能 | 不增面是否等于零成本？每档增加约 191 KB，是明确代价；后续比较稀疏数据或指骨方案，不声称预算通过。 |
| QA/发布 | 数值闭合能否证明接触？不能，图片反例保留。源/双档已生成，九动作、全七人、真机与完整发布门禁未完成。 |
