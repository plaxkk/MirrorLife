# 掌形与持物近景复核

## 玩家目标与裁决

改善探索、交谈和照料活动中主角手掌过厚、遮住手指的轮廓，保留真实三维环绕、已有操作和分指。本轮仍是隔离候选，未安装或发布；全七人生产美术目标未完成。

缩短掌体后，交谈与抬手近景的手指露出更清楚，但端杯俯视图明确暴露张掌持物：杯柄贴近手掌，四指没有环握。**握点数值通过不能作为持物美术通过。** 当前手形仍有硬折面，不放行生产验收。

## 实现与复现

在 hand-atlas-v2 上启用 `ATRIUM_HAND_FORM_STUDY=1`：手局部负 Z 的掌体/指蹼坐标缩至 .72，掌厚按区域渐减最多 10%；不直接编辑手指原始体、控制变换。后续重构/减面仍可能改变最终指尖，未声称最终端点精确不变。默认构建关闭开关，开启时强制输出到 tmp。

构建同时设置 `ATRIUM_RESIDENT_IDS=you`、`ATRIUM_CUFF_STUDY=1`、`ATRIUM_HAND_DIGITS_STUDY=1`、`ATRIUM_HAND_ATLAS_STUDY=1`；`ATRIUM_BUILD_ROOT` 为 `tmp/portrait-study/hand-form-v1`，Blender 执行 `scripts/build-atrium-residents.py`。不启用已否决的通用身体图集扩色。

## 验收证据

证据目录：`evidence/atrium/hand-form-study/`。

- `v1-mobile/`：四组肩肘腕诊断姿态，每组三向与左手近景。人工查看交谈和抬手腕部，掌部覆盖减少，未见上一轮黑斑；仍有块状指节。这是桌面 Chrome 移动视口，不是真机。
- `v1-gaps.json`：沿用上轮“间隙数量增加”的检查失败，因为基线已有四指。保留原结果；新增显式 retain 模式，默认 increase 不变。`v1-gap-retention.json` 确认左手四截面为 2/3/4/4，右手 3/4/4/4，与基线相同；每手源审计 900 面、一个连通分量、零非流形边。这证明分指保持，不能证明进一步增加或解剖质量。
- `v1-contact/` 与 `v1-contact-close/`：真实 E 键触发浇水/泡茶，位置由检查夹具设置，不是完整步行旅程。补充杯子反向、俯视角后，人工确认张掌持杯缺陷；近景版 23 个有效握点样本，最大锚点误差约 1.99e-15 米、页面无错误。报告明确限定为握点坐标检查，不是手指表面接触或碰撞检查。
- `v1-runtime.json`：实际 GLTFLoader 解码双档，左右手各 880/849 个顶点，每档合计 20,748 次基础层纹理邻域采样；颜色、粗糙度、法线最大误差 .001961，手与身体 UV 越界为零。不覆盖远 mip。
- 两档纹理 UV、Python/JavaScript 语法与 diff 检查通过。`v1-deformation.json` 保存八组源姿态拉伸检查；不等于完整动作或手指碰撞验收。
- `v1-resources.json`：桌面 2,285,396 B / 26,404 面，移动 901,256 B / 24,341 面；均 6 材质、7 绘制单元。相对 hand-atlas-v2 桌面增加 5,720 B、移动减少 2,372 B，面数不变；未测新帧时间，不宣称性能改善。

## 五视角复核

| 视角 | 反对意见、证据与裁决 |
| --- | --- |
| 玩家/产品 | 轮廓改善是否让照料更可信？手指露出改善，但端杯张掌仍破坏可信度，不能称体验完成。 |
| 游戏设计 | 改手形会否阻断活动？实际 E 键两活动可触发，未改变游戏逻辑；未覆盖取消/连续操作全路径。 |
| 美术 | 单面看似握住是否靠遮挡？反向/俯视证实没有环握，是本轮最强反对意见，保留候选不安装。 |
| 工程性能 | 新掌形会否增加渲染负担或串色？面数/材质不增，实际纹理采样通过；真机与帧时间仍待验证。 |
| QA/发布 | 数值接触检查是否误导？明确限定锚点验证，补充实际缺陷图片，不把通过结果当发布证据。 |

## 后续与目标复核

下一步应制作能随持物状态弯曲的手指与拇指握姿，再从杯柄两侧、俯视和动作过渡检查；继续缩掌无法解决刚性张掌持物。需同步源、双档与九动作后再考虑安装，并检查释放时恢复自然手势。当前没有新线上用户反馈、完整七人验收或真机性能结果；推送仍受此前自动审批限制。
