# MirrorLife Runtime Art Bible v1

适用范围：城市地图、可行走室内、剧情卡与选择 UI。目标不是把三层界面做成同一张皮，而是让玩家始终认得这是同一个世界，并能快速分辨“环境、证据、行动、后果”。

## 共同视觉语法

| 轴 | 运行时规则 | Token / 实现 |
| --- | --- | --- |
| 主色 | 暖纸色承载信息，深墨色建立边界；青绿表示共同照料，珊瑚表示当前行动，金色表示证据与方向。单个画面最多一个高饱和主动作色。 | `paper #fff8e8`、`ink #30364e`、`teal #4e9b8f`、`coral #ee775f`、`gold #efc65a` |
| 轮廓 | 地图标签、室内导视和剧情选择使用 2px 深墨轮廓；重要叙事卡允许 4px 右下硬阴影。3D 模型依赖真实几何边缘与接触阴影，不使用 inverted-hull 描边。 | `--runtime-outline`、`--runtime-offset-shadow` |
| 形状 | 信息卡采用 16px/7px 轻微不对称圆角；操作控件采用 14px 圆角；空间物件用圆角实体和可读的真实厚度，不用平面卡片冒充家具。 | `--runtime-card-radius`、`--runtime-control-radius` |
| 字体层级 | 地图与操作使用 Noto Sans SC/PingFang；叙事标题使用 Noto Serif SC/宋体回退。正文最小 14px，主动作至少 700 字重；移动端不以缩小字号换取完整显示。 | `--font`、`--font-display` |

## 三层落地

- 地图：建筑名牌使用 paper/ink、2px 轮廓和统一无衬线；人物保留青绿/珊瑚/金色语义色。人物不得与建筑、标签或主角小于 8px，局部聚集不超过 2 人。
- 室内：墙地保持低饱和暖色，交互语义色来自同一 teal/coral/gold 组；家具必须有真实厚度、世界包围盒和碰撞合同。前景家具不得占屏 25% 以上，不能为单一机位删除可旋转空间。
- 剧情：标题使用展示字体；事实、未来与行动卡复用 paper/ink 轮廓和硬阴影。珊瑚只表示玩家即将提交的动作，金色表示可见证据，青绿表示共同完成或恢复。

## 角色与光

核心角色在 idle/listen/respond/walk 的四方向中维持同一服装主色和皮肤材质。脸部由真实场景光照亮，不做距离切换的平面脸；四向脸部亮度中位数不得低于场景的 0.75 倍。手物接触优先于夸张姿势，脚滑、穿插和肘膝断裂都属于发布阻断。

## 空间与性能边界

形状语言不能突破空间合同：主通道 1.4m、交互净空 0.9m、静默站位修正 0.15m、锚点修正 0.25m。移动完整场景以 225k triangles / 110 draw calls 为软预算；语义 LOD 必须保留“它是什么、能做什么、为什么重要”，优先删除不可见细分和重复材质。

## 每次改动的交叉验收

1. 玩家：十秒内能否说清当前目标、可行动作和世界为何暂停或推进。
2. 美术：主色、2px 轮廓、圆角形状、字体层级是否仍属于同一套语言。
3. 空间物理：四向旋转、站位、锚点、通道、GLB/碰撞世界包围盒是否通过真实 runtime 门禁。
4. 性能：Interactive Ready 不得后移；Full Ready 的传输、GPU 上传、triangles 和 draw calls 不得突破设备预算。

实现入口：CSS token 位于 `game.css :root`；Canvas/室内共享值位于 `public/game.js` 的 `MirrorLifeRuntimeArtBible`；核心 Blender 模型使用同一 ink/teal/coral/gold 暖纸色谱。
