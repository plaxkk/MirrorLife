# MirrorLife 室内 3D 完整还原标准

## 定义

“完整还原”不是让模型从某一个角度看起来相似，而是把已确认的物件设计还原成可从任意方向检查、可继续编辑、可优化并可在游戏中交互的完整资产。

单张等距插画没有提供背面、底面和遮挡部分的信息，因此不能单独证明完整还原。缺失的信息必须先通过一致的多视图设计明确下来，再进入 3D 制作。Three.js 只负责游戏运行时的渲染、灯光、动画和交互，不承担正式模型的造型还原。

## 正式资产流水线

1. **隔离原始物件**：使用独立无污染的 2D 物件图作为艺术方向基准。
2. **锁定七视图**：制作 front、back、left、right、top、bottom、isometric 七张一致视图，并人工确认相机、比例、颜色和隐藏结构。
3. **候选重建**：Tripo/Hunyuan 等图生 3D 输出只能作为候选高模，不得直接进入正式运行时目录。
4. **Blender 精修**：逐部件修正轮廓、厚度、连接关系、背面、底面、UV、材质、尺度、原点和部件层级。
5. **保存源资产**：必须保留原生 `.blend` 文件，同时导出未简化 interchange GLB。
6. **生成 Web LOD**：从高模生成独立的浏览器 LOD，不得用正式高模直接冒充 Web 模型，也不得反向把低模当源资产。
7. **可量化比对**：七个规范视图逐一进行轮廓与颜色比对，并由人工确认每个语义部件。
8. **360 度验收**：至少 12 帧转台检查隐藏缺口、漂浮部件、错误背面、纹理接缝和轮廓跳变。
9. **游戏内验收**：近景、常规探索距离、遮挡、碰撞、拾取和交互动画均需通过。

## 禁止晋级的资产

- 单图挤压、深度图浮雕、平面卡片或 sprite billboard。
- 仅靠 Three.js 基础几何拼出的近似物件。
- 未人工修正的单图转 3D 输出。
- 没有背面/底面设计或以随机猜测代替多视图确认的模型。
- 只有 GLB、没有可编辑 Blender 源文件的模型。
- 高模与 Web LOD 完全相同，或通过删除关键部件满足性能预算的模型。
- 只在一个镜头下相似、转动后轮廓或部件关系明显错误的模型。

## 自动门禁

`npm run verify:interior-3d:release` 必须同时验证：

- 七视图文件互不重复，最短边不少于 1024 px；
- `referenceProvenance` 已人工批准，且每个视图通过独立创作、相机匹配、比例锁定和隐藏结构设计检查；
- 原生 `.blend` 高模、未简化 master GLB 和独立 Web GLB 均存在；
- 模型闭合、无开放边和非流形边，并满足 Web 三角面与文件体积预算；
- UV、纹理分辨率、部件层级、真实尺度、隐藏几何和材质色板均已复核；
- 七视图比对、语义部件清单和 360 度转台均由人工批准。

开发占位模型可以保证游戏持续可玩，但在上述门禁全部通过前，报告必须保持为 `development`，不得宣称完成还原。
