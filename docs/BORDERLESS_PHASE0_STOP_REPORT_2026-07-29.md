# Borderless Phase 0 停止报告（2026-07-29）

## 结论

根据规格 §14 的停止规则：三次结构性尝试均未形成可接受的、可复现的
800ms 入口证据时，必须停止 Phase 0，不得继续第四次结构/修复迭代，不得
放宽预算。Phase 0 在此停止，等待架构决策。

生产行为已通过新的 revert commits 恢复到最后完整通过的 Task 3 基线
`9ca0b4b`；只撤回了 Task 4 commits `3748f20`、`dbecaaa`、`d9501ba` 和
`7da5516`，Tasks 1–3 保持不变。

## 三次结构性尝试

1. **仅加载 runtime**：entry render-ready `3228.0ms`，失败。
2. **目标资源 + Rapier 预热**：prewarm `1330.7ms`、ready `2408.8ms`、
   controllable `2494.1ms`，失败。
3. **隐藏目标场景 / shader / Rapier 预热**：没有有效的验收样本。最后一次
   优化前，入口函数返回后的下界为 ready `858.2ms`、controllable `858.9ms`
   （仍超过 800ms）。随后出现的 `784.1/784.5ms` 与 `566.9/567.2ms` 名义
   样本无效：计时排除了 `enterInteriorView` 的同步工作，且隐藏 payload 与
   权威实际场景的演员/出生点不精确一致，不能作为验收依据。

## 独立审查发现

- 新鲜回归暴露目标内容不一致：预热保留了 `maternity-hospital`，实际目标为
  `kindergarten`。
- 演员不一致：预热使用 `i` / frame `3`，实际使用 `j` / frame `0`。
- 预热玩家位置 `(0, 3.72)` 与 public-plaza 权威 Rapier spawn
  `(.22, 1.38)` 不一致。
- 入口计时从 `enterInteriorView` 同步工作之后才开始，掩盖了真实用户可用
  时间；额外回归还存在顺序掩盖与 stale compile 覆盖不足的问题。

## 未满足的物理/性能条件与残余风险

隐藏场景路径的投机预热本身约为 `11.8–13.4s`。即使它不阻塞地图，这一长
GPU/资源工作量仍使稳定、可复现且物理上等价的 800ms 入口证明不可得。该
条件在当前架构下被视为阻塞，而不是通过调整测试或预算解决。

## 等待的决策（不在本报告中选择）

1. 改变架构，例如采用可验证的场景状态转移/常驻渲染生命周期；
2. 缩小 Phase 0 范围，取消或延后目标场景预热；
3. 明确改变性能预算及其端到端计时定义。

在作出其中一项决定前，不继续 Phase 0 或 Task 5，也不进行 Production
部署。
