# 衣片编辑源回流与袖窿修形（2026-09-24）

## 目标与裁决
目标保持七人高标准还原、生产美术、真实可玩 3D、性能和发布反馈。本轮为后续实际衣物修形建立可验证的源文件回流，并处理 lin 腋下夹折。首次玩家的进入/移动/靠近/交谈/离开循环不改；希望环绕人物时衣物更可信，而非只让某张截图更顺眼。

**完成了几何/权重编辑源回流；未完成成衣美术。** 袖窿抬高候选正面尖折略缓和，但背面行走仍有明显折线，内搭/主要衣褶未改善。不替换正式资产，不以源文件通路完成代表七人生产完成。

## 先诊断再修形
`ATRIUM_CAST_REST=1` 不执行初始 60 帧待机更新，直接拍摄载入模型。夹折仍存在，说明主要问题已在源形状中；该观察不证明所有姿态都无变形问题。报告以 `initialPose` 区分两种夹具，三个后续行走采样仍由实际角色更新器驱动。通用 scope 中原先固定写 idle 的措辞已修正。

## 编辑源入口
新增 `ATRIUM_PANEL_CAGE_INPUT`，必须启用隔离衣片构建。读取名为 `Garment panel cage` 的对象并转移到当前角色骨架，验证：

- 源文件不能等于输出编辑笼路径，避免覆盖用户的修形输入。
- 衣片和骨架对象局部变换、绑定骨骼矩阵、五个支持的顶点组必须匹配；未应用的形态键明确拒绝。
- 顶点坐标、面片和权重在复制时逐项精确验证；权重显式重建，避免清理顶点组时将它们清空。
- 最终源记录输入路径、SHA 和导入范围；临时导入的骨架/父对象移除，不进入角色场景。

入口目前支持衣片几何和权重修形。材质由项目配色重新指定，UV 仍走现有生成/批处理流程；不能称为完整材质、UV、形态键编辑回流。

无修改回流实测：核心网格 7,697 顶点、14,674 有向面片，其坐标/权重/颜色与前轮源精确一致（允许面片循环起点和顶点编号差异）。这不宣称整个 GLB 字节相同，也未验证其他网格无关字段与未使用眼白 UV。

## 五视角交叉评审
- 玩家/产品：质疑改善是否在实际游玩尺度可感知。近景只有有限收益，不能由局部测试推定真实交谈体验；需要回到玩家路径比较。
- 游戏设计：质疑源修形是否带来动作代价。表格明确保留反向抬臂退化；道具接触和动作连续性仍缺证据。
- 美术：最强反方是背面折线和整体直板感仍突出。已查看行走背面与移动 LOD 侧面，反方成立，候选不通过生产美术。
- 工程：质疑所谓可编辑源是否真正进入导出。无修改回流、编辑输入 SHA 与最终源元数据、实际图像变化共同证明几何/权重通路；其他编辑类型不在支持范围。
- QA/发布：质疑未加载正确源或将复制错误藏在最终截图。入口断言、核心有向面片对照与来源报告回答本轮范围；正式文件未替换，不发布。
