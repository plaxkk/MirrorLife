# 全员表面制作：下一阶段执行规格

状态：设计中，不能据此宣称已实现。前置门禁：先解决外套阶段的桌面性能疑点（顺序对照原模型 P95 18.4ms、新模型 33.0ms），用交替对照与材质成本诊断判断影响后，再开展全员推广。承接完整人物生产美术 goal，不替代 `ATRIUM_PRODUCTION_ART_GOAL.md` 的其余门禁。

## 玩家终点与范围

目标玩家在进入中庭后的 30 秒内看到统一的真实 3D 居民，在前 5 分钟的探索与对话中辨认居民的脸、发型与衣装，不被黑亮、塑料感或局部贴图拼接分散注意。完成交流和决策后继续探索的原循环、输入、碰撞、反馈与存档保持。

本阶段将已验证的主角表面制作管线扩展为全员可编辑的皮肤、发丝、织物与鞋面材质；优先利用现有网格，不靠堆面数。形体、发束轮廓、面部身份和表情仍要继续专门精修，材质不代表这些目标完成。无新增玩法或人物身份变更。

## 预算与保真

- 原场景上限保持 180 calls / 500,000 triangles / 220 geometries。表面制作不新增网格或 primitive。
- 桌面 P95 60fps、移动 P95 30fps 原门禁不变；保留所有失败样本，不用桌面模拟替代真机。
- 为本阶段新增资源设置暂定制作上限：相对外套阶段桌面人物 GLB 合计增加不超过 7 MB，移动不超过 3 MB。它是额外资源的上限，不是证明弱网体验可接受。
- 身体纹理：主角桌面 1024 / 移动 512；居民初始桌面 512 / 移动 256。皮肤和发丝需先做单人多向原型，再确定纹理尺寸。
- 保留完整眼睑与口部形变、骨架绑定、九段动作、透明与双面规则及连续 3D 视角。不得用固定镜头或隐藏背面通过截图验收。

## 实现假设

1. 分别制作身体、脸部、头发的明确材质输入，避免继承有歧义的旧节点状态；源文件保持可调参数。
2. 身体的粗糙度元数据区分皮肤、衣料和鞋面。织物细节只作用于布料；皮肤与鞋面必须有独立响应。
3. 面部原有唇色、颊色与眼睑色保留，统一原生头部与新建眼睑的运行 UV，加入克制的微表面变化；必须在中性、闭眼、说话三种状态检查接缝。
4. 头发使用沿发束方向的细节与根梢变化，不能把随机噪点当作发丝。先验证源节点与真实 GLB 的一致性。
5. 所有贴图在实际 GLB 中解码检查覆盖、尺寸、色彩空间和无重复顶点乘色，再进入运行截图。

## 五视角反对意见

| 视角 | 可证伪的反对意见 | 验证方式 |
| --- | --- | --- |
| 玩家 / 产品 | 新纹理只在极端近景有效，正常探索没有收益 | 正常游玩距离、对话和多角度的同镜头对比；没有收益的细节不扩大到全员 |
| 游戏设计 | 静态面部好看，但眨眼、说话或转头出现接缝 | 七人中性/闭眼/说话，连续转头和完整交互录像 |
| 美术 | 脸上噪点像脏污，头发像塑料或织物 | 单人多光向原型、正侧背近景，先否决不自然候选再推广 |
| 工程 / 性能 | 更多贴图抵消了已有加载和帧率优化 | 逐档资源体积、真实输入端到端启动、GPU/帧时间分位数和全场景预算 |
| QA / 发布 | 皮肤误用织物法线，LOD 丢图，嘴眼形变被重建 UV 破坏 | 解码贴图测试、材质家族回归、形变通道/控制器验证和运行多姿态截图 |

最强反方结论：现有发帽、脸部和服装形体问题不能只靠材质解决。若材质原型不能改善真实视角，应返回形体与发束设计，不能继续批量烘焙以制造进度。

## 验收与发布

先完成一位居民的原型并与主角方向对齐，证据通过后才推广到七人。最后重新走正常和异常路径、两档性能和完整录像。检查通过后提交并推送项目分支；生产发布、真机、长时稳定性及实际用户反馈按完整 goal 继续追踪，不由本阶段代签。
