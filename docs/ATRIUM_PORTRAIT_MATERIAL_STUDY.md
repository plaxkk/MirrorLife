# 面部材质与眼形制作

## 目标与反对意见

近景皮肤缺少唇色和区域光泽，眼神较弱。尝试肤色/粗糙度分区及稍高的眼部开口，保持身份、肤色、头型、原动作与几何预算。全场景 180 calls / 500,000 面 / 220 geometries 预算不变。

五视角自审（不是独立人工签收）：

- 玩家：是否能在正常交谈距离看出更自然的神态？要求全身/近景同镜头，而非只看材质球。
- 设计：静态开眼变大可能破坏眨眼和说话。源网格闭眼射线、部分闭眼及自然动作分别验收。
- 美术：色差可能像化妆，光泽可能加重塑料感，图集可能出现新瑕疵。均须保留反例，不为通过检查而采用。
- 工程：增加贴图不能挤占设备预算。记录双档实际字节/面数，未做候选帧时验收，不引用旧运行性能作为候选成绩。
- QA/发布：有贴图不代表有有效 UV。新增实际 GLB 材质/UV 约束及 Blender 回归，发布仍需后续完整验收。

## 导出错误与修复

v1 烘焙有有效像素，但实际 GLB 头部没有 TEXCOORD_0，出现黑色高光表面。v2 尝试刷新依赖图没有解决，否决该归因。直接在 Blender 中记录烘焙前后的属性证实：遍历 `list(color_attributes)` 删除第一项后，后续 RNA 引用因属性索引变化而失效，误删 UVMap，留下 FaceResponse。

改为先取名称，再逐项重新查找删除；断言保留 UVMap 且颜色属性全部移除。另保留皮肤源材质的 specular/coat 参数到烘焙材质，避免烘焙时悄悄回到默认值。

新增 `scripts/verify-atrium-textured-uv.py`，每次居民 master/桌面/移动导出后验证贴图要求的 TEXCOORD 存在且 VEC2 数量匹配位置。现有 14 个运行 GLB 通过，损坏 v1 被拒绝，修复样稿三档通过。

可复现 Blender 回归 `scripts/verify-atrium-bake-uv.py`：打开当前源而不保存，加入第二颜色层，实际烘焙和导出头部，检查 10,497 个 UV loop、移除颜色层、Basis/Blink/Talk 坐标逐项不变，以及导出 TEXCOORD。回归通过；日志在 `evidence/atrium/portrait-material/uv-regression/`。

## 材质与眼形候选

v3 使用肤色顶点绘制与区域粗糙度：克制的唇色、面颊/耳部暖色、额头/鼻部/唇部独立光泽。标准 PBR 贴图为桌面 512px、移动 256px，不烘焙光照。观察到唇色更清楚，但整体脸颊/鼻口仍有塑料感，不能声称达到生产美术。

v4 保持 v3 材质，眼球 Z 缩放 .48→.56，开口上缘 .012→.016、下缘 .008→.009；虹膜比例相应减小。由实际眼部几何重新生成闭眼包络。源闭眼 4964/4964 射线覆盖，最小 head-local 间隙 .001882。四分之一、半闭、四分之三闭眼均保存前/侧面；移动模拟自然眨眼 578 样本、范围 0..1，触控对话峰值 .84978，无 pageerror。这不是手机真机、口型同步或用户美术认可。

## 图集暗边诊断

v3/v4 颈部有细线。仅去掉 normalTexture 时细线仍存在；把皮肤贴图换成常量材质后消失。两个诊断 GLB 只用于归因，不作为角色候选。v5 增大皮肤 UV 岛间距和烘焙扩展，已观察到颈线消失，但耳部仍有暗边；v6 延展纯黑背景仍未充分解决耳部问题。

v7 按源肤色范围识别包含黑色背景的半覆盖边缘像素，向未覆盖区域延展附近有效颜色，同时断言所有有效像素逐值不变。该处理仅用于独立皮肤材质；眼睛、眉毛、头发属于其他网格，不能将此方法任意用于带有黑色绘制特征的贴图。增加红通道占优断言，保证该下界在颜色插值时仍成立；不同调色板必须重新设计覆盖判断。桌面正侧面与闭眼图保留肤色，颈耳暗边在检查画面中消失；移动 256px 同镜头中性侧面也未见该暗边。正面仍有塑料感，闭眼存在细小纹理/轮廓问题，眼睑、眉毛与面部体积衔接仍不合格。因此 v7 保留为隔离样稿，不安装。
