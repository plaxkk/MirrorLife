# 实时界面模糊与桌面帧时间

玩家终点：首次进入后可以流畅环顾、走向居民、读到提示，再探索两层并完成共同决定。保留真实 3D、人物活动、碰撞、阴影、交互提示和原画质分辨率；继续使用 180 calls / 500,000 triangles / 220 geometries 预算。此次修改只移除地点、菜单按钮、目标卡、对话框和抽屉的背景模糊，保留原来的暖色半透明底、边框和阴影。

## 诊断

上一候选（提交 `fac8beb`，保留原始测量 JSON）桌面 P95 为 100.4ms，GPU P95 20.42ms。先检查帧循环、GPU 查询、HUD 更新和渲染设置，再在同一可见 Chrome 页面中交替开启/关闭五处 backdrop-filter；没有隐藏人物或 HUD，没有降低像素比、几何或阴影画质。

初次四段各约 16 秒环绕对照（`evidence/atrium/compositor/orbit-ab.json`）：原界面 P95 49.4 / 34.2ms，关闭模糊后 17.6 / 17.5ms；四段均保持窗口焦点、没有 Long Task 条目。动态人物和环绕输入不是逐帧相同，因此又用固定镜头四段交替复核，方法与原始结果见 `fixed-camera-ab.json` 和 `scripts/profile-atrium-compositor.mjs`。

这些对照支持“实时背景模糊对本机帧时间有显著成本”，不能解释上一轮全部 100ms 长尾，也不能证明所有硬件都受同样影响。WebGL GPU 查询不覆盖浏览器整个合成流水线；其数值与 rAF 的差异不是精确的合成耗时。没有把两者直接相减，也没有声称完成系统级根因追踪。

固定镜头复核：开启模糊的 P95 为 49.7 / 34.2ms，关闭后为 17.6 / 17.5ms，四段无 Long Task 条目。这组窗口页面可见但 `document.hasFocus()` 均为 false；它是同状态诊断，不能冒充有焦点的实际输入验收。截图确认目标卡仍可读，背景轮廓会轻微透出，这是取消背景模糊的实际视觉代价。

修改后的独立构建测量：桌面 1920×1080 / DPR1 的 P50/P95/P99 为 16.7/17.6/17.7ms，移动模拟同为 16.7/17.6/17.7ms。桌面峰值 87 calls / 494,357 triangles / 76 geometries，移动模拟 70 / 303,221 / 72，仍在原预算内。桌面严格 P95≤16.67ms 判定仍为 false，不能把接近 60fps 的短时样本写成全部稳定性验收通过。

## 五个视角的反对意见

以下为按职责进行的自审，非外部人工审核。

| 视角 | 可证伪的反对意见 | 验证方式 |
|---|---|---|
| 玩家/产品 | 去掉模糊后提示或对话难读 | 保留原有高不透明度暖色底；比较 blur-hud / flat-hud 运行图，并检查实际对话截图 |
| 关卡设计 | 性能变好是因为隐藏人物或固定了玩家镜头 | 仅 CSS 五处声明改变；完整键盘回游重新验证两座楼梯、探索与决策，固定相机只用于诊断 |
| 美术 | 面板风格与场景不一致 | 保留配色、圆角、边框和阴影；对照截图检查文字与背景分离，不改变既定空间美术方向 |
| 工程性能 | 对照受镜头和负载变化影响，短时改善不能代表稳定 60fps | 交替重复并补固定镜头对照，再跑完整独立桌面/移动样本；保留失败基线和各轮分位数，真机与长时门禁不豁免 |
| QA | HUD 改动会遮挡交互或失去触屏响应 | 不改变布局、事件或显示条件；重跑异常恢复、触屏移动、坐立、握持与连续流程 |
