## 运行与操作

在项目目录执行 `npm run dev -- --host 127.0.0.1 --port 4193`，打开 `http://127.0.0.1:4193/atrium.html`。正式构建执行 `npm run build`，随后 `npm run preview -- --host 127.0.0.1 --port 4194`。

游戏欢迎页和菜单均有“天井生活馆”入口。本轮使用独立入口保护原室内系统及其未提交修改，没有替换所有房间。

- WASD / 方向键行走，Shift 快走；拖动鼠标环顾，滚轮缩放。
- E 交谈、使用、坐下或起身；Esc 取消对话；J 打开手记。
- 触屏使用左下摇杆、右侧拖动和交互按钮。设置中可切换桌面/移动画质、查看对照镜头、开启提示音。
- 示例：与桌边林晓、陈屿交流 → 后侧轮值手记 → 右侧照料植物 → 回共享桌选择晚间安排 → 从主楼梯上楼 → 安静角交流、查看录音 → 西楼梯回茶饮区 → 退出重入。

这是一段本地、确定性的示例剧情。没有依赖付费或外部生成服务。

## 空间与参考边界

一层外轮廓约 22×16m，层高 3.5m；楼上三边回廊及西前落脚平台构成第二层。包括入口、共享桌、阅读、茶饮、植物、二层安静角及观景角，两条楼梯回游。

约 470m² 是初始可用面积估计，不是测绘实测。按楼板外轮廓相加、扣除角落重叠后的毛面积约 495m²；墙体、家具和楼梯占用尚未做严格可用面积测算。参考图未提供尺寸，后立面、前立面、西回程梯及上层深处是设计补全，不是精确还原。

校准相机：位置 `[-3.4, 2.65, 6.8]`，看向 `[1, 2.8, -2]`，垂直 FOV 62°，16:9，1920×1080。玩家镜头独立，允许连续自由移动。`gallery-cameras.json` 记录其他美术检查镜头；这些检查镜头不代替回游录像。

资产重建顺序：`build-atrium-assets.py` → `refine-atrium-source.py` → `polish-atrium-circulation.py` → `refine-atrium-library.py`；随后 `build-atrium-residents.py`、`build-atrium-life-props.py`、`export-atrium-kit.py`；最后 `node scripts/export-atrium-motion.mjs` 与 `bake-atrium-motion.py`。Python 脚本用 Blender 的 `--background --python` 运行，不是系统 Python。

仅修改已有建筑源后，可用 `export-atrium-assets.py` 重导，不必重建整个场景。`report-atrium-assets.mjs` 记录体积、GLB 声明统计、SHA-256 和检查边界。

最新建筑步骤需在 `refine-atrium-library.py` 后执行 `polish-atrium-forms.py`，其后执行 `bake-atrium-contact.py`，最后同步 `export-atrium-kit.py`。接触遮蔽图为 `public/assets/atrium/floor-contact.png`，烘焙参数在同名 JSON，纹理也打包进建筑 `.blend`。它是短距离静态可见性烘焙，不是完整 GI；移动家具后需要重新烘焙。运行时投影见 `src/atrium-floor-contact.js`，不依赖固定验收镜头。

执行 `npm run verify:atrium:release` 可自动构建并启动本机 4195 端口临时预览，顺序运行可见 Chrome 截图、桌面/移动模拟性能、握持、异常和带录像的完整回游；结束后关闭临时预览。此命令生成证据与预算判定，不代表自动通过美术或真实手机门禁。

本轮新增的 `repair-atrium-furniture-collision.py` 应在建筑布置完成后运行，再执行 `bake-atrium-contact.py` 和 `export-atrium-assets.py`，保证安静区椅子的位置、碰撞与接触阴影一致。镜头复用运行时 GLB 建索引，无额外模型文件；CPU 查询三角面与渲染三角面分开报告。完整验收现包含四向/双指操作专测和从原始数据自动生成性能报告。

## 预算与测试口径

180 draw calls、500,000 triangles、220 geometries 继续作为本双层试点的观察上限，没有静默提高。统计 `renderer.info` 每帧主画面加动态人物阴影；静态建筑阴影在加载时生成一次，其时间计入加载。三角面包含重复渲染通道，不等于唯一资产面数；geometry 数为 GPU 几何对象，不等于 Blender 对象数。

桌面主要测试为 AMD Radeon Pro 5300M、Chrome 152、1920×1080、DPR 1。移动结果为同一桌面 GPU 上 390×844、设备 DPR 3、渲染 DPR 上限 1.25 的触屏模拟，不是真机结果。性能采样与录像分开执行；保留失败基线，不以最好一次结果取代全部记录。

加载报告包括页面导航至就绪、脚本启动至就绪、点击“走进”至首个活动帧。网络来自本机预览服务器，不能外推到公网或弱网。JS heap 可获取；显存、整机游戏进程内存和真实手机功耗未测得。

- 光照：已做天窗/侧窗光、环境填充、静态和动态阴影，续作增加两层地面短距离遮蔽；专业 GI、侧窗明暗层次与柔和植物投影仍未完成。
- 人物：续作改为连续头发体块、贴合脸面的五官、完整手指和独立握持锚点，移除长袖内部的裸前臂覆盖层。握持坐标和道具尺度已有运行检查，但不能代替手指表面接触验收。人物比例、肩部过渡、织物细节、自然表情仍不足；玩家新增台阶高度 IK 与逐帧骨骼指标；完整鞋底网格穿透、世界坐标脚底锁定、斜走/快跑/转身仍未全面验收。眨眼和说话仍是简化动作。
- 探索：有记录与对话反馈，但空间声音线索、真实录音内容、更多居民自主生活安排未完成。共同决策的实际演出有限，不能把意向文字当作 NPC 已经完成搬动或换房间。

- 稳定性：桌面帧时间存在环境相关波动，必须继续查明并做长时间真实游玩；没有真实移动设备或公网/弱网验收。
- 发布：本轮不是生产上线验收，不执行生产部署。

## 五个视角的反方审查

下列为本轮按五种职责进行的自审，不是虚构人工评审。

| 视角 | 可证伪的反对意见 | 当前证据与结论 |
|---|---|---|
| 玩家/产品 | 玩家可能不知道去哪，热点只是说明文字 | 有目标计数、附近提示、完成动作才落记录和后续对话；首次用户是否觉得好玩仍缺用户测试 |
| 关卡 | 二层/侧室可能只能截图，无法连贯走通 | 输入驱动录像与回游物理测试；已修正实际卡点。全部角落的探索舒适度尚待人工试玩 |
| 美术 | 程序建模可能只是有颜色的几何体，与参考成品质感有明显差距 | 多角度和人物近景直接呈现；接受该反对意见，美术门禁仍不通过 |
| 工程性能 | 面数降低并不保证帧时间稳定，首进和重入可能卡顿 | 保存设备、分位数、输入延时及渲染通道统计；不得只凭平均帧率通过 |
| QA | 快速操作、取消、失败恢复可能重复扣状态或丢进度 | 单元/物理/真实浏览器异常用例；已验证路径通过，真机与长时压测仍未完成 |

## 本轮经验

建模检查必须从房间内部看书架，背板和书脊方向不能只看建模正视图。楼上交汇口的栏杆必须按真实可行走楼板判断，不能按二维外轮廓一圈包围。桌边坐姿需要同时校验座面高度、骨骼髋部与对话转向。性能必须注明 Chrome 是否可见并保留波动结果。
