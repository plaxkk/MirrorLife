# MirrorLife 2D 身份到 3D 角色管线

## 设计判断

主界面的 2D 头像不应被直接挤出、贴到平面卡片或交给单图重建后原样上线。单张头像缺少侧面、背面、服装层级和遮挡信息，直接转换会产生身份漂移、错误四肢与廉价的“会转动贴纸”感。

MirrorLife 将头像视为角色身份规范，由以下四层共同保持一致：

1. **轮廓层**：头身比、发型外轮廓、帽子与背包决定远距离辨识。
2. **色块层**：发色、主服装色、下装色和 10% 强调色与头像逐帧映射。
3. **职业层**：画具、安全帽、实验外套、眼镜、观察帽、探险帽、厨师帽和导师围巾。
4. **动作层**：同一共享骨架驱动，但站姿、倾听、记录和交互姿态允许按身份微调。

当前运行时已经使用 `avatarFrame -> ACTOR_STYLE_PROFILES` 的显式映射，避免只按职业重新猜测人物。八个身份分别是：创作者、建造者、植物研究者、学习者、观察者、探索者、厨师和导师。

## 量产流程

1. 从头像生成正面、45°、侧面和背面角色设定图，并人工确认发型、帽子、外套、鞋和随身物。
2. 复用一套 1:3.5 头身比基础网格，制作 4 种体型；身份差异优先由头发、服装和配件实现。
3. 使用共享骨架，统一髋、膝、肩、肘、手掌和面部注视骨骼；鞋底接触点统一为地面原点。
4. 每个身份制作 LOD0/LOD1/LOD2，材质限制在皮肤、头发、服装、配件四套以内，移动端优先切换 LOD。
5. 输出 GLB 后保留 `avatarFrame`、`identity` 和配件插槽元数据，游戏状态只传身份帧和动作，不在运行时猜模型。

## 验收标准

- 只看剪影时，八个身份两两可区分。
- 头像与 3D 模型的发色、主服装色和标志性配件一致。
- 正面、侧面和背面均无穿模；背包、外套和长发参与遮挡。
- 脚滑误差小于 0.03m，鞋底离地误差小于 0.015m。
- 单角色 LOD0 不超过 35k 三角面，移动端 LOD1 不超过 12k，远景 LOD2 不超过 3k。
- 四名角色同屏时仍能保持 60fps 桌面目标和 30fps 移动端下限。

当前 Three.js 模块化角色是可玩的身份保真基线；后续替换为美术制作的共享骨架 GLB 时，不需要改变剧情、存档和社会分身数据结构。
