# Quick Design Spec: 余波路线

**Type**: Addition

**System**: 双线回声 / 30 分钟单局导航

**GDD Reference**: `docs/COUNTERFACTUAL_EPISODE_VERTICAL_SLICE.md` — 30 分钟单局结构

**Date**: 2026-07-16

## Change Summary

完成一个房间后，下一章不再只用 toast 告诉玩家“去街道寻找某建筑”。系统在真实街道上保留一条五章余波路线：显示本集完成度，把镜头引向下一栋建筑，并让建筑持续发光；玩家仍需自己辨认并点击建筑进入，不进行自动传送。

## Motivation

当前单房间微循环和整集终章都可玩，但场所之间缺少连续动作。玩家离开房间后会从强叙事状态落回完整开放世界，下一目标只出现一次，极易在 12–20 分钟中段流失。余波路线服务三种体验：

- **胜任**：玩家始终知道这一集完成到第几章、下一步在哪里。
- **自主**：系统只聚焦与高亮，不代替玩家进入或完成房间。
- **连续性**：五个物理建筑被同一条故事线连接，街道不再是叙事加载页。

## Design Delta

当前实现：

> 点击“下一章”后退出室内，仅显示“去街道上寻找某建筑”的短暂提示。

新规则：

> 点击“下一章”后激活本集余波路线，镜头聚焦下一建筑；街道显示五章节点和下一章名称，目标建筑获得限时金色呼吸轮廓。玩家点击任一章节节点可以重新聚焦，但只有点击世界中的建筑才能进入。

## New Rules

1. 第一处本集建筑被探索后锁定 `activeEpisodeThreadId`；只有当前故事完成后，其他故事才能自动接管路线。
2. 路线节点严格读取 `interiorExploration[zoneId].scenePlayed`，不能用 UI 本地状态伪造完成度。
3. “跟随余波”只改变世界相机、目标高亮和提示，不改变角色坐标、场所完成状态或剧情证据。
4. 点击已完成或未完成节点都可聚焦对应建筑，终章节点不可提前打开。
5. 进入室内时收起街道路线上下文；回到街道后自动恢复。
6. 路线可收起但不会遗忘；刷新后从 `state.story.activeEpisodeThreadId` 恢复。

## Tuning Knobs

| Knob | Default | Safe Range | Effect |
| --- | ---: | ---: | --- |
| `EPISODE_TRAIL_FOCUS_MS` | 7000 ms | 4000–10000 | 目标建筑呼吸高亮持续时间 |
| `EPISODE_TRAIL_ZOOM` | 1.18 | 1.0–1.4 | 聚焦后街道镜头倍率 |
| 路线节点 | 5 | 4–6 | 一集可读的章节数量 |

## Affected Systems

| System | Impact | Action Required |
| --- | --- | --- |
| 双线回声 | 记录当前故事线 | 复用 `state.story` 持久化 |
| 室内旅程 | 下一章按钮传递真实 `zoneId` | 替换仅提示逻辑 |
| 街道相机 | 根据建筑物理布局聚焦 | 不改变世界实体坐标 |
| 世界渲染 | 目标建筑限时描边 | 使用现有 zone rect |
| 响应式 HUD | 五节点桌面横排、移动端横向滚动 | 不遮挡主操作 |

## Acceptance Criteria

- [x] 完成房间后点击“下一章”，真实退出室内、出现五节点路线并聚焦正确建筑。
- [x] 聚焦不会自动进入建筑或修改 `scenePlayed`。
- [x] 目标建筑有可见呼吸轮廓，7 秒后自动结束；再次点击节点可恢复。
- [x] 完成度和下一章从真实存档恢复，刷新不重置。
- [x] 桌面 1536 × 1024 与移动 390 × 844 无横向页面溢出，路线可收起。
- [x] No regression: 室内物理、场景选择、五场所终章和镜像接力继续通过。

## GDD Update Required?

No. 这是现有 30 分钟垂直切片中“场所之间如何连续”的实现补齐，不改变核心玩法规则。
